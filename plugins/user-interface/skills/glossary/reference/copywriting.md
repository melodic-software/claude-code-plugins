# Copywriting terms

How words guide and reassure. Each entry gives the term, a definition, and the line between it and
the term most often confused with it.

## Copywriting: `copywriting`

### Microcopy: `microcopy`

Short UI text: labels, error messages, placeholders, tooltips. Has an outsized effect on how
trustworthy a product feels.

**Versus:** body copy is long-form text; microcopy is the short text on controls and states.

### Error message: `error-message`

Text explaining what went wrong and how to fix it. Invalid input names nothing. Your email must
include an @ symbol names everything.

**Versus:** an inline error is where the message goes; an error message is what it says.

### Sentence case: `sentence-case`

Capitalizing only the first word and proper nouns. The default for UI labels. Title Case On
Everything reads like a legal document.

**Versus:** title case capitalizes every major word; sentence case only the first word and proper
nouns.

### Inline error: `inline-error`

An error message next to the field that caused it. A summary at the top of a form makes users hunt.
Inline is unambiguous.

**Versus:** an error summary lists all errors at the top of a form; an inline error sits next to its
field.

### Tone: `tone`

How the voice adapts to the moment. The same product can be encouraging during onboarding, neutral
in settings, and careful around destructive actions. Same voice, different register.

**Versus:** voice is the constant personality; tone shifts with the moment.

### Destructive language: `destructive-language`

The copy on actions that cannot be undone. Delete, remove, disconnect, revoke. Should be
unambiguous. Softening it with neutral language like clear or reset when the action is permanent
misleads users about the consequences.

**Versus:** a confirmation dialog is the prompt; destructive language is the wording on the action
itself.

### Truncation strategy: `truncation-strategy`

Deciding where and how text gets cut when it overflows. A name truncated mid-character is worse than
one cut at a word boundary. Titles, labels, and descriptions each need their own truncation logic.

**Versus:** text overflow is the rendering behavior; a truncation strategy is the decision of where
and how to cut.

### Numeric formatting: `numeric-formatting`

How numbers are written in the interface. 1,000 vs 1000. 3.5k vs 3,500. $1.00 vs $1. Consistency
matters more than the specific convention, but the convention should match the user's locale.

**Versus:** tabular nums is about digit width; numeric formatting is how the number is written.

### CTA: `cta`

Call to action. The label on the primary action. Save changes builds more trust than Submit. Own the
action, do not apologize for asking.

**Versus:** a secondary action sits beside it; the CTA is the label on the primary one.

### Placeholder: `placeholder`

Hint text inside an input that disappears when the user starts typing. Cannot replace a label. By
the time they need the reminder, it is gone.

**Versus:** a label stays visible and names the field; a placeholder disappears when typing starts.

### Front-loading: `front-loading`

Putting the most important word first. Export ready beats Your export is complete and available for
download. Users scan.

**Versus:** scannability is the whole quality of quick-read text; front-loading is one technique for
it.

### Voice: `voice`

The consistent personality behind all the words in a product. Formal or casual, technical or plain,
warm or neutral. Voice stays the same regardless of context. Tone shifts within it depending on the
situation.

**Versus:** tone shifts with the moment; voice stays the same.

### Success message: `success-message`

Confirmation that an action completed. Often neglected. Should be specific (Saved, not Done), and
brief. A success message that reads like a press release has missed the point.

**Versus:** an error message reports a failure; a success message confirms a completed action.

### Scannability: `scannability`

Text written to be read quickly rather than thoroughly. Short sentences, active voice, key
information first. Most UI copy is never fully read. Writing for scanning is not dumbing down, it is
respecting the user's attention.

**Versus:** front-loading is one technique; scannability is the whole quality of text written to be
read quickly.

### Contextual help: `contextual-help`

Explanatory text placed close to the thing it explains, at the moment the user needs it. Different
from a tooltip, which requires hover, and from documentation, which requires navigation. The best
contextual help is a single sentence that removes the need to ask.

**Versus:** a tooltip requires hover and documentation requires navigation; contextual help sits
beside the thing it explains.
