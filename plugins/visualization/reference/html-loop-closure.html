Loop-closure and export reference

Snippets an interactive rendered view copies so the reader can hand something back, and so live page state can leave the page. Self-contained: no external links, scripts, fonts, or images. Every demo below runs from this file alone.

Doctrine lives in the convention, not here. When a view owes an export, which genres this family is excluded from, and why payloads stay terse are stated in docs/conventions/rendered-views/README.md, section "Loop closure and the export obligation". The escaping and self-containment rules are that document's "Security baseline". This file demonstrates both and owns neither.

These snippets own no page shape. Each adopting lane keeps its own layout, vocabulary, and genre. Copy a helper and a pattern; do not copy this page.

The four shared helpers

Every pattern below is built from these four and nothing else. Copy all four, or the subset a pattern names. The snippet blocks in this section are printed from the live functions this page is running, so what you read is what executes.

esc: the one interpolation path

Use it for every value that reaches markup, in text and in a quoted attribute alike. & is replaced first, so an already-escaped entity is not double-decoded. The safer path is still not to interpolate at all: node.textContent = value needs no escaping, and the patterns below prefer it wherever the value is a whole text node.




copyText: the clipboard boilerplate


One copy of the write-then-fall-back-then-flash sequence that every interactive page otherwise reinvents. The flash element is written with textContent, never innerHTML. It returns whether the copy landed, so a caller reports a failure instead of showing a false confirmation.





safeHref: URL position, which esc does not cover


Escaping keeps a value inside its attribute; it does not make the value safe to navigate to. javascript:alert(1) contains none of the characters the baseline escapes, so it survives esc unchanged and still runs on click. Any value that lands in href, src, action, formaction, or SVG xlink:href is scheme-checked first and escaped second. A relative URL is rejected too: a self-contained view has nothing to resolve it against.





downloadText: export without a data URL


Exports build a Blob and an object URL rather than concatenating content into a data: URL. A data URL puts the payload in URL position, where it needs percent-encoding rather than HTML escaping, and data:text/html in particular runs script. The object URL is minted by the browser from bytes, so no input reaches the URL string, and it is revoked once the click is dispatched. The download filename is reader-reachable too, so it is reduced to an allowlisted character set before it becomes an attribute.








  
Positions escaping does not reach. The convention's character-escape rule covers text and quoted-attribute positions. It does not cover URL position (use safeHref), a download filename (use safeFilename), an unquoted attribute (always quote), a value inside <script> or <style> (never interpolate there, per the baseline), or a CSS url(). A view that needs one of those and has no helper for it emits the value as visible text instead.





Pattern 1: numbered resonate tokens


The cheapest rung. Items carry stable visible numbers; the reader names the numbers back in chat. The page needs no state and no script beyond the render. Reach for this when the reader is picking from a list you already had to show.

    Pattern 2: chip-assembled reply
    

    The reader toggles chips and the page assembles the terse payload for them. Use it when the reply has a fixed vocabulary the reader should not have to spell. The payload stays short on purpose: the page is still on screen, so the agent re-anchors by token rather than by a restated body.
    

    
  
    
  
    
  
    
    
    
  
    

    

    


    Pattern 3: generated follow-up prompts
    

    The page writes the next prompt for the reader, one button per branch. Use it when the useful next moves are known at render time and typing them is the only friction. Each prompt is a whole text node, so it is set with textContent and never interpolated.
    

    
  
    
  

    

    


    Pattern 4: accept and correct sign-off
    

    The escalation for a view the reader approves rather than picks from. Every row is accepted or corrected; a correction carries free text, which is the first payload in this family that is not a token, and so the first that is untrusted on the way back out.
    

    
  
    
  
    
  
    
    
    
  
    

    

    


    Pattern 5: live-state export
    

    The top rung, and the one a custom editor always owes. The page holds state the reader changed, so the export reads that state and rebuilds the record: markdown, a diff, or plain text. Build the string from state, never by scraping innerHTML, and offer both rungs: the clipboard for a payload the reader pastes into chat, a file download for a payload that is a document.
