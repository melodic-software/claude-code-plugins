Rendered-views chrome reference

Tokens, type, and the accessibility floor for this marketplace's person-facing HTML views. Self-contained: no external links, scripts, fonts, or images.

Type and chrome

Serif for headings: --serif (ui-serif, Georgia).

Sans for body: --sans (system-ui).

Mono for code and labels: --mono (ui-monospace).

Borders are 1.5px solid; panels round at --radius-panel (12px), rows at --radius-row (8px).

Accessibility floor (provisional)

RuleToken or mechanism
Body text contrast--slate on --ivory (and the inverse in dark scheme); --gray-500 only for secondary text at 1rem or larger
Link and accent text contrastText never wears --clay directly (2.96:1 on --ivory, below the 4.5:1 floor): links use --link, the clay-derived --clay-deep in light scheme (5.37:1 on --ivory) and --clay-soft in dark (4.89:1 on --gray-700)
Accent is never the only signal--clay and --olive stay decorative: they accompany a text label or shape change, never carry meaning alone
Focus visibility:focus-visible gets a 3px --focus outline with 2px offset, at or above the 3:1 non-text floor in both schemes (styled above)
Color schemecolor-scheme: light dark plus the prefers-color-scheme token flip above
Motionprefers-reduced-motion: reduce disables animations and transitions wholesale
Keyboard reachEvery interactive control is a native element or carries a tabindex and key handler

Self-containment

A rendered view ships as one file: inline CSS and JS only, no external requests, assets as data URIs when unavoidable. Escape any interpolated content; the rendered-views convention owns the escaping baseline.
