No related issue: a CI gate fix found while unblocking the standards sync in #18775.

## Summary

A standards sync that changes a managed copy under a fragment-mode plugin fails `changelog-fragments-required`, so every such sync needs a hand-added `none` fragment before it can merge. This PR exempts a verified standards-sync pull request from that gate, the same way a verified Dependabot pull request is exempt.

## Fix

- `scripts/lib/changelog-fragments.sh`: the Dependabot check becomes `bot_only <base> <login> <email>`. `dependabot_only` and the new `standards_sync_only` call it with their bot's login and noreply address.
- `scripts/check-changelog-fragments.sh`: `--check-required` passes a fragment-mode plugin with no fragment when the pull request author is `melodic-standards-sync[bot]` and every commit is that bot's, committed by GitHub, with a signature GitHub verified. A commit anyone else pushes onto the branch still requires a fragment. The blocker variable is renamed `CF_BOT_BLOCKER`, since either bot can now set it.
- `check-vendor-version-bump.sh` still exempts Dependabot only: no post-merge fragment is written for a sync.

## Loosened checks

- `changelog-fragments-required` (`scripts/check-changelog-fragments.sh --check-required`) now accepts a change set with no fragment when it is the standards-sync bot's alone. Why: the files it changes are managed copies of `melodic-software/standards`, byte-exact with their source, so they carry no plugin release of their own and ride the plugin's next release. Without the exemption each sync needs a manufactured `none` fragment, a manual step that stops the sync for something other than intent or security. The exemption keeps the Dependabot check's proof: PR author, per-commit author and committer, and GitHub's signature verification, so a hand-pushed commit cannot use it.
