# Page lane

The surface registry (`surfaces/registry.mjs`, run from SKILL.md "Question lanes") routes here when it resolves the page: the user asked for it, or `surface` is `page` in planning's user config. `<plugin-root>` is the placeholder SKILL.md "Spoke paths" defines. This file arrives unexpanded, so each `${user_config.KEY}` token below stands for the value SKILL.md "Question lanes" shows for that key: put that value in its place. Page protocol: [`surface.md`](surface.md). The question shape and its rules every lane shares: [`question-shape.md`](question-shape.md).

**Question surface: the page.** Start the page with the command below before the first round and ask no round inline. The page is a local page on 127.0.0.1 that this session watches; the registry names the default, falls back to it for an unknown or unset value, and gives the one-line note for a real unknown value. When the resolution's `available` is false, skip the start and take the degrade below. The page is two-way and is the input surface: the user answers each question there and every save reaches this session. The terminal stays a valid input, mirrored onto the page with `record-terminal`. A decision this session records or revises in the ledger is mirrored the same way. `surface: page` wins over `use_ask_user_question`, which applies only when the surface is `terminal`. The user may ask for the page at any point, whatever the setting. On a dense terminal round, offer the page; when the page cannot start, offer the read-only table. Start it with one command; the data dir sits in the memory slice, never CWD-relative:

```bash
bash "<plugin-root>/surface/round.sh" --dir '<memory_dir>/<topic-slug>/interview-surface' ensure-running --open --emoji-markers '${user_config.use_emoji_question_markers}' --pacing '<question_pacing>'
```

`<question_pacing>` is the value SKILL.md "One question at a time" resolves through its cascade, the repository files included; resolve it before this start, not at the first round.

**The round's layout on the page.** Give each topic its own `groups` entry and set each question's `group`: the rail's Groups view lists the round under those topic headers. The round's first question carries the round's header card. A question held for an in-flight lookup is posted with a `wait` op (`by: claude`); the header card's `Held:` line names it, with every other question still held from this round or an earlier one, and what each waits on, until the hold clears. Under `single` pacing every later question of the round carries the `Held:` line too. A decision the evidence settles is not posted as a question: its `Settled by evidence:` line goes in the round's restate text on the header card, its `answered` row goes straight into the ledger, which `sync-ledger` keeps as a row only the ledger has, and the next question posted takes the id after it. Under `single` pacing (`--pacing` records it, and anything but `single`, an unexpanded token included, reads as `round`), `add-round` posts the round with its first question only, each later question goes out with an `add` op in the same round once the one before it is answered. When the user asks for the other pacing in the session, rerun the start command without `--open` and with `--pacing` set to it.

Then write the frontier with `add-round` and arm the watcher as a background Bash task. Write the register's `open` rows in the same step with `round.sh --dir '<memory_dir>/<topic-slug>/interview-surface' sync-ledger --ledger '<memory_dir>/<topic-slug>/interview-checklist.md'` (the start command's `round.sh`), which rewrites the register rows from page state; the frontier-rounds contract (recommendation, basis, alternatives, probe, partial rounds, gates) holds on the page as it does inline. When Python, curl or bash is missing, the port cannot bind, the server stays unreachable after a restart (the watcher exits 2), or the session runs on a remote host the browser cannot reach, render the read-only decision table instead and say in one line which prerequisite failed. Substitution record: a value counts as set only when SKILL.md "Question lanes" shows it substituted. A token it shows literal is unset, whatever the key's saved state or `default`: the registry reads a literal `surface` token as unset, and emoji markers fall back to on, the option's default, since the start command passes the token through and `round.py` reads anything but false, 0, no or off as on. Which values substitute into skill content: [manifest reference "Reference a saved value"](https://code.claude.com/docs/en/plugins/manifest-reference#reference-a-saved-value) and the `default` field of [User configuration](https://code.claude.com/docs/en/plugins/manifest-reference#user-configuration); our probe of an unset key with a `default` is the `/harness-ops:plugins` record "`userConfig`: an unset key renders the literal placeholder". Probe record, Claude Code 2.1.312, 2026-10-28 ([#9886 host run](https://github.com/melodic-software/claude-code-plugins/issues/9886#issuecomment-6468043702)): in fresh `claude -p` sessions a saved boolean `true` substituted as the text `true`, and an unset key with a `default` arrived as the literal token. As of 2026-10-28; recheck when either section changes, or when that record or the #9886 probe is re-run on a newer release. A forced wrap-up names what it skipped: the `wrapup` event's text starts `Skipped before wrap-up:` (`round.sh status` prints it), and the wrap-up reports each skipped item to the user. Wake command, events, rules and wrap-up exports: [`surface.md`](surface.md).

## SKILL.md steps on this lane

Each item below is the lane part of a SKILL.md step; the step's own rule and its halts still hold.

- Step 2, a recommendation's `Checked against:` line. On the page it opens the question's `facts` field, each constraint named in words, since the page's wording lint flags a bare `C<N>` ([`surface.md`](surface.md) "Wording lint").
- Step 3, confirmation gate: it runs on the page. Post the restatement with a `restate` op and wait for the user's `confirm-understanding` event, per [`surface.md`](surface.md) "Confirmation gate". The page's `restate` keeps the full recap, not the `--changed` one.
- Step 3, procedure check: this lane's restatement box offers commitment ticks, so SKILL.md's exception applies here. The rows held open by unticked commitments are the ones `round.sh status` lists on `accepted, to confirm:` lines.
- Step 4, Brief cross-check (and its Gates twin): add `--surface '<data_dir>'`, which checks the Brief against the page's export ([`surface.md`](surface.md) "Wrap-up" lists what it fails).

## Exit codes

`round.sh` exits 0 when done, 1 when refused (the message names the cause), 2 when a prerequisite is missing (Python 3, or curl for `ensure-running`), 5 when `ensure-running` started the page server but it did not answer, and 6 when `export-ledger --diff` or `ledger-check` finds the page and the ledger disagree, or a ledger merge kept a conflicting row. `watch.sh` exits 2 too when curl is missing. Exit 2 or 5 from `ensure-running` takes the degrade; on exit 6, reconcile the rows it prints and carry on. `round.sh --help` lists the codes, and [`surface.md`](surface.md) "Start and stop" covers the watcher's own codes and the recovery for each.
