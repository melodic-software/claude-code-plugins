# Hand off (Step 5)

Read this at the stop boundary, before recommending a next step (SKILL.md Step 5). `<plugin-root>`
is the placeholder SKILL.md "Spoke paths" defines.

**A user who arrived mid-flow, unsure what was settled or which stage the work is in**, gets `/session-flow:workflow`, which works out the stage from what is on disk; recommend it before guessing a pipeline step. **A general (non-engineering) session is terminal**. It produced a shared-understanding summary, not a Brief; deliver that summary and stop, offering no pipeline handoff (nothing downstream consumes it), unless the confirmed understanding is work to build that needs a spec: then offer `/planning:prd` when its product intent (users, success measures) is still unsettled. **An engineering session** wrote a PLAN.md Brief. When the Brief defers a question only a named person other than the user can answer (an assumption-sweep `person` item the user could not answer, or a `tenant` item whose owner is not the user), also recommend `/planning:interview document <topic>`, this skill's document surface ([`lane-document.md`](lane-document.md)), which turns it into a document that person fills in under the row's own `Q<N>`; it runs beside the next step, not in place of it, and only when the user asks for it. When the confirmation's Terms and ADRs part holds a new or renamed project-glossary term, recommend that change first (SKILL.md "The confirmation's parts, in order"), then the next step per task shape:

- **Product intent still unsettled after confirmation (who the users are, how success is measured)** → `/planning:prd`, which locks it before the engineering steps below

- **Code change** → `/planning:design`, since exploration and research already ran as lookups during the interview ([`lookups.md`](lookups.md)) and run no second pass here. `/planning:design`'s handoff writes PLAN.md's `## Design` before `/planning:plan`. Design-significant work (new types or contracts, a new module or library, a package-topology, cross-module, or data-model change) gets its design rounds there; work with no design question open records the one-line early exit in one step. **When the task is small, not design-significant, and the contract IS the plan**, proceed directly to implementation (`/implementation:implement` if enabled) instead; small design-significant work still goes through `/planning:design` first
- **The outcome feeds a prototype** → one prototype per question the Brief's `Prototype <n> proves:` criteria name, each handed to the prototype skill that fits it and built in its own worktree, so they run at once ([`prototype-questions.md`](prototype-questions.md))
- **The approved Brief is one unit of work that a later session, an AFK lane or another person picks up** → `/work-items:track add --agent-ready`, one tracker item carrying the Brief's acceptance criteria and any design part it already holds; the session that picks it up runs design and plan from there
- **Interview outgrew one session (branches keep opening faster than they close, or the user or harness asks for a pause)** → route the next step with `/session-flow:workflow` (if enabled), handing it the ledger and Brief paths and the first open branch; without session-flow, follow the pointer below. The ledger + Brief survive; resume continues from the first open branch. Before the first resumed round, resolve the surface through `<plugin-root>` again (never an absolute path copied from a save-point) and run `round.sh --dir '<memory_dir>/<topic-slug>/interview-surface' doctor --ledger <ledger>`, which lists what the running version needs and the ledger lacks ([`surface.md`](surface.md) "Resume"). When it outgrew the session because the effort is too big AND still foggy, recommend `/planning:wayfind` instead (SKILL.md Stance), which charts from the same ledger
  - **Pointer**: when the interview outgrows the session and session-flow is not enabled, fetch <https://code.claude.com/docs/en/context-window#when-your-context-fills-up> live.
