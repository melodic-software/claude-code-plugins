# Hand off (Step 5)

Read this at the stop boundary, before recommending a next step (SKILL.md Step 5). `<plugin-root>`
is the placeholder SKILL.md "Spoke paths" defines.

**A user who arrived mid-flow, unsure what was settled or which stage the work is in**, gets `/session-flow:workflow`, which works out the stage from what is on disk; recommend it before guessing a pipeline step. **A general (non-engineering) session is terminal**. It produced a shared-understanding summary, not a Brief; deliver that summary and stop, offering no pipeline handoff (nothing downstream consumes it). **An engineering session** wrote a PLAN.md Brief. When the Brief defers a question only a named person other than the user can answer (an assumption-sweep `person` item the user could not answer, or a `tenant` item whose owner is not the user), also recommend `/planning:questionnaire` (if enabled), which turns it into a document that person fills in; it runs beside the next step, not in place of it. Recommend the next step per task shape:

- **Code change with unknowns about the codebase** → clear context, then codebase exploration (`/discovery:explore` if enabled. It reads the Brief as scope)
- **Code change relying on external libs/APIs/best-practices** → external research (`/discovery:research` if enabled)
- **Already understand the codebase and the externals** → `/planning:design`, whose handoff writes PLAN.md's `## Design` before `/planning:plan`. Design-significant work (new types or contracts, a new module or library, a package-topology, cross-module, or data-model change) gets its design rounds there; work with no design question open records the one-line early exit in one step. **When the task is small, not design-significant, and the contract IS the plan**, proceed directly to implementation (`/implementation:implement` if enabled) instead; small design-significant work still goes through `/planning:design` first
- **The approved Brief is one unit of work that a later session, an AFK lane or another person picks up** → `/work-items:track add --agent-ready`, one tracker item carrying the Brief's acceptance criteria and any design part it already holds; the session that picks it up runs design and plan from there
- **Interview outgrew one session (branches keep opening faster than they close, or the user or harness asks for a pause)** → route the next step with `/session-flow:workflow` (if installed), handing it the ledger and Brief paths and the first open branch; without session-flow, follow the pointer below. The ledger + Brief survive; resume continues from the first open branch. Before the first resumed round, resolve the surface through `<plugin-root>` again (never an absolute path copied from a save-point) and run `round.sh --dir '<memory_dir>/<topic-slug>/interview-surface' doctor --ledger <ledger>`, which lists what the running version needs and the ledger lacks ([`surface.md`](surface.md) "Resume"). When it outgrew the session because the effort is too big AND still foggy, recommend `/planning:wayfind` instead (SKILL.md Stance), which charts from the same ledger
  - **Pointer**: when the interview outgrows the session and session-flow is not installed, fetch <https://code.claude.com/docs/en/context-window#when-your-context-fills-up> live. **As of**: 2026-10-13. **Recheck trigger**: the section changes how it splits work between compaction and a fresh session, or moves.
