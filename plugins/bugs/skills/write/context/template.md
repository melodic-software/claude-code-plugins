# `/bugs:write` template

Loaded on demand by `/bugs:write`. Contains: the full Markdown template (5 fields), the `--file` frontmatter, and the "No bug confirmed" form.

## Full template

Default emission (stdout) — no frontmatter:

```markdown
# Bug: <title in present tense, one line>

**Severity**: <low | medium | high | critical>
**Suggested fix location**: `<file path>` `<function or class name>` (no patch)
**Reported by**: <reporter identity, or session ID>
**Reported at**: <ISO-8601 timestamp>

## Steps to reproduce

1. <step>
2. <step>
3. <step>

## Expected behavior

<what should happen>

## Actual behavior

<what does happen>

## Severity justification

<one sentence: why this severity. Cite blast radius / blocking factor / data-integrity impact>

## Notes

<optional: anything the reporter said that doesn't fit above; flag any (unknown — needs reporter confirmation) entries here for traceability>

---

*Generated by `/bugs:write` (stdout mode). To file it as a work item, hand it to `/work-items:track add`*
*when that plugin is installed; otherwise rerun with `--file` and then `gh issue create --type Bug*
*--body-file <report path>` (org repos; on repos without native Issue Types omit `--type Bug` and add a*
*`type: bug` label when the repo defines one) (let `gh` prompt for the title), or use an available tracker MCP tool.*
```

## `--file` mode frontmatter

When writing to a file, prepend:

```markdown
---
type: bug-report
date: <ISO-8601 UTC, e.g. 2026-05-02T14:30:00Z>
slug: <slug>
severity: <low | medium | high | critical>
fix-location: <file path>
---
```

ISO basic timestamp in the filename (Windows-safe, no colons): `20260502T143000Z`. Example filename: `20260502T143000Z-bug-pricefor-discount-math.md`.

Append this footer after the report body when writing to a file:

```markdown
---

*Generated by `/bugs:write` (--file mode). To file it as a work item, hand it to `/work-items:track add`*
*when that plugin is installed; otherwise in a GitHub repo `gh issue create --type Bug --body-file <this*
*report path>` (org repos; on repos without native Issue Types omit `--type Bug` and add a `type: bug`*
*label when the repo defines one) (let `gh` prompt for the title), or use an available tracker MCP tool.*
```

## When the report is "no bug confirmed"

When the survey and Q&A reveal no defect, do not emit a bug report. Emit this summary instead:

```markdown
*No bug confirmed.*

**Description claimed**: <what the user said>
**Verified state**: <what the source/test/run actually shows>
**Recommendation**: <close the loop / capture it as a feature request / open a question elsewhere>
```

This preserves the read-only contract while saving the user from filing a phantom issue.
