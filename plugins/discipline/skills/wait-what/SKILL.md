# Wait. What?

I lost track of your last reply. Go back to the last point I clearly
followed and explain again from there, adding the context I was missing.
Write it in ASD-STE100 Simplified Technical English (short sentences, one
meaning per word, technical terms exact) and use the terms the project
itself uses for its domain. Read the nearest domain glossary or context map,
per the project's own convention, when one exists; with none, plain technical
English alone.

## Boundaries

- **One-shot repair, not a corrector.** It re-pitches the one message that
  lost its reader and sets no standing posture; the re-pitch is the repair.
- **Re-ground, not compress.** Full technical precision stays and the missing
  premise comes back. A shorter, blunter reply that is no clearer is the
  failure this skill exists to avoid.
- **No glossary is a silent no-op, not an error.** The vocabulary half drops
  without comment; the register and missing-context halves always apply.
- **Only the reader fires it.** The model cannot tell its reader stopped
  following, so `disable-model-invocation: true` stays and no
  `discipline-batch` tier is set.
- **Siblings.** `/discipline:tighten-your-output` when the problem is too many
  words; `/discipline:mind-your-maxims` when the standing communication
  discipline needs re-anchoring. If installed, `/education:explain` when the
  reader needs the idea simplified, not the message re-grounded, and
  `/adhd:clarify` when the content is right but the shape is wrong.
