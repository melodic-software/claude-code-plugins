# The release note format

A release note is the one page a downstream team reads before upgrading. The rules for writing
one sit in [SKILL.md](../SKILL.md); this file holds the format.

## Rules

- **Lead with the upgrade risk.** Put what breaks before what is new
- **Name the owner.** Every note says who to ask about it
- **Push back on vagueness.** If the author cannot articulate WHY the change matters, interview them with the one-question-at-a-time dialog (SKILL.md "Interview step") before writing anything. A bad note is worse than no note
- **Revise when reality shifts.** Notes change. When a release slips, update it. Do not leave a stale note steering upgrades
- **Keep it short.** Our own limit is one screen; past that, link the changelog.
