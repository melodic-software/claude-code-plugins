# Git catalog: status and index cost, scalar, maintenance, partial and sparse clones, worktrees, network, trace2

Git causes of slow local commands and fetches, Windows included. Every row is a pointer record: a
finding that cites it re-reads the pointer live in that run, and a row's measure is the first step,
not a result. Every row is a single-publisher attribution to what Git's own 2.56 docs, source or
release notes state (MEDIUM), so every row seeds only a candidate finding.

Measure with trace2: set `GIT_TRACE2_PERF` (or `GIT_TRACE2_EVENT`) to an absolute file path in the
child process environment. `git -c trace2.perfTarget=...` writes nothing, because git reads
`trace2.*` only from system and global config. Wall time is the `exit` event `t_abs` and phase time
is a region's `t_rel`, both in seconds; work is the named `data` counters. Status timing is labeled
"status without index refresh" and runs `git --no-optional-locks status --porcelain`. Every trace2
region or counter name below is confirmed in the live trace before a finding uses it. Any remedy that
changes a global or repository git setting is a later-horizon `steps-for-you` item that go-faster
never applies.
