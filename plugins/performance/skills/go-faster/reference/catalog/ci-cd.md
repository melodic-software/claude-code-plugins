# CI/CD catalog: GitHub Actions queue, caching, concurrency, required checks, matrix, runners, re-runs

GitHub Actions causes of slow pull-request and deploy runs. Every row is a pointer record: a finding
that cites it re-reads the pointer live in that run, and a row's measure is the first step, not a
result. "GitHub states" marks a behavior only GitHub's own pages document (single-publisher, MEDIUM).

Measure from the REST runs and jobs endpoints (read-only). go-faster measures per-job queue time
with `findings.py ci-timing`, which reads `started_at - created_at` from the REST jobs endpoint
(queue formula MEDIUM: `needs`-gated `created_at` timing was observed on one repository),
excluding `conclusion == skipped`.
`gh run view --json jobs` carries no `createdAt` (MEDIUM), so it cannot give queue time. The run
`/timing` endpoint is documented as closing down with no removal date found (MEDIUM); it is never a
measure source. CI time is reported as counts of minutes and runs, never as a price.
