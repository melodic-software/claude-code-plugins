### Added

- `/overengineering:justify` judges a proposal before it is built: a plan step, a design option, or a described mechanism such as a branch, a workflow and a ruleset. For each mechanism it names the existing control that already covers the same risk and drops what one covers, keeps an abstraction for a stated, known repetition with a namable shape, and names the option with the fewest moving parts. Planned mode is read-only and persists nothing. Its description now also triggers on a proposal ("is this overengineered", "do we need X", "is there a simpler way"), and two outcome eval cases cover each side of the line.
