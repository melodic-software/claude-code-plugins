### Added

- **A `file_names` `userConfig` option is the per-person layer** ([#18002](https://github.com/melodic-software/claude-code-plugins/issues/18002)). It holds your own `file_names` keys as one JSON object and takes the place of the user-global `~/.claude/docs-naming.json`, per the config-cascade layers. It merges where that file did: under the team and personal override files, adding to the policy-floor keys and ignored for `generated`. A value that is not one JSON object is reported and ignored, and one holding a whole old file (`{"schema": 1, "file_names": {...}}`) is read as its `file_names` object. Every skill passes the option to its scripts through a new `--user-config` flag, and `scripts/resolve-config.sh` also reads `CLAUDE_PLUGIN_OPTION_FILE_NAMES`.
- **`setup-apply.sh --user-config-value`** previews copying the old user files' keys into the option: per file, the keys it would add, then the merged value and a `values.json` for `claude plugin configure`. It writes nothing. `/docs-naming:setup apply` shows the preview, and on a yes gives the native command that saves it, leaving the old file in place.

### Changed

- **`~/.claude/docs-naming.json` and `~/.claude/docs-hygiene.json` are read only while the option is unset or invalid**, the first that exists, in the option's place. Each `resolve` run that finds either file prints one warning naming each file and the option. With a valid option set, neither file is read. A later change removes the read.
- **The resolver names the per-person layer `userConfig`** in `layers` provenance and in each tier's `_layer`, where it said `user-global`. `paths` prints a `userConfig file_names` row (`present`, `absent` or `invalid`), then one row per old user file (`legacy` when read, `legacy-unread` when not). `/docs-naming:setup check` shows a `layer userConfig` row and an `old user file` WARN row per file.
