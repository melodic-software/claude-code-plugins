### Added

- `/debugging:debug diagnose` runs the loop and hypothesis phases only: it stops at the confirmed cause at file:line with the loop output, removes its instrumentation and changes no other code.
- Phase 1 opens with a surface pass: `/app-control:drive ready` when the project has a control skill, otherwise the manifests and launch config, then the surfaces the app type has. It never assumes a port, and turns each source it cannot reach into a request for scoped access, never for a secret.
- Phase 3 reads the domain glossary first and checks what each environment runs (deployments, the deployed ref, workflow runs for the deployed commit, recent tickets) as a lead to test, never as proof.
- The post-mortem lists lessons about driving the app for `/app-control:map refresh` to place, and the always-on signal step points at `/implementation:implement` for observability-by-default design.
