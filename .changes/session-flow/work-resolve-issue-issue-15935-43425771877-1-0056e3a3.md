### Changed

- `/session-flow:retro` now asks, for each finding, whether a check could decide it before choosing where the finding should live, in session mode's Phase 3 where recommendation rows are written (quick mode follows the same step). If a check could, the row is a check proposal and retro writes no CLAUDE.md, AGENTS.md or rules-file row for that finding. It sends the check to `/corrections:codify` when that plugin is installed, and otherwise to its catalog's Hooks section and the enforcement ladder. The catalog's target sections now run strongest first: Hooks, Settings, CLAUDE.md / Rules, then Memory. Retro proposes a CLAUDE.md or rules line only when no check on the enforcement ladder can decide the finding, or the check fails the ladder's guardrail criterion. The number of repeats before retro proposes a check now follows `/corrections:codify`'s `recurrence.min_occurrences` setting.
