### Added

- **Stable question ids.** `round.sh next-id --ledger <ledger> [--dir <data dir>] [--count <n>]` prints the next free ids after the highest one held, and the ledger export keeps every number a ledger row already has instead of renumbering. `check-open-questions.sh` accepts a gap in ids only where a hand-written `- gap | Q<a>-Q<b> | <why>` line declares it, and `export-ledger --ledger` keeps those lines. `export-ledger` and `sync-ledger` write `- gap | Q<a>-Q<b> | never assigned` for ids nothing ever held, never for one the ledger held, and a gap line past the last row reserves those ids.
- **Register tags and `round.sh reopen`.** A register row's resolution can end in `kind::`, `problem::`, `depends::`, `reopened::` and `recheck::` tags, which import and export carry unchanged. `round.sh reopen --ledger <ledger> Q<N> --round <n> --fact-file <file>` reopens an answered row under its own number, keeps the old answer and the fact in `## Reopened answers`, and flags every row built on it with `recheck::`, which blocks `check-open-questions.sh` until `reopen --rechecked` clears it.
- **Round detail levels, `scope-check` and `measures`.** `round.sh show --level full|standard|minimal <round-N.md>` prints a saved round at that detail level (full byte for byte; no level hides the recommendation with its reason, `Withheld:`, `Discovery:`, `Second view:`, `Departs from:`, `Flips if:` or `Commits you to:`), set by the new `question_detail` setting (default `standard`). `round.sh scope-check` prints the counts for a round header's `Scope check:` line, and `round.sh measures` prints rounds, median lines per shown round and reopened answers. `check-round-codes.sh` also fails a question with no single `My recommendation:`, `Withheld:`, `Discovery:` or `Strong answer:` line, and a round header without exactly one `Scope check:` line.
- **Interview flow: gap triage, held questions, a blind recommender and stable ids.** Before round 1, `/planning:interview` sorts every unknown into a lookup, a discovery question or a decision question; when discovery questions exist, round 1 asks only those, open, each with a `Discovery:` line and no recommendation (new `context/lookups.md`). A question a running lookup could change is held on the `Held:` line, at most one dispatch runs per lookup skill, and a fact that contradicts an answer runs `round.sh reopen`. Each round's recommendations come from the new read-only `interview-recommender` agent, which sees the facts, constraints and settled decisions but not the conversation; a differing draft shows as `Second view:` and a departure from a settled decision as `Departs from:`. New ids come from `round.sh next-id`, problems are numbered P1, P2 and tagged on their questions, the round header's `Scope check:` line comes from `round.sh scope-check`, the end sweep reports every finding for the disposition pass to filter, the glossary is read at the start of every interview and a term is written only after the user confirms its restatement, and `/planning:audit-answers` never auto-accepts a `kind:: discovery` row.

### Removed

- **The interview's per-round contradiction pass.** `/planning:interview` no longer dispatches a sub-agent before each round to check the draft against earlier answers. The end sweep still finds contradictions and asks each as one question naming both sides, and an answer that conflicts with an earlier one is still caught when it is given. The legacy eval case `pre-round-contradiction-pass` is removed with it.
