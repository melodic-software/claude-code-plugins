### Fixed

- `run-validity.py` has a new `skill loaded` check. It fails a run whose skill load aborted on its pre-computed command, and names the case and run. It reads both abort texts, `Shell command failed for pattern` and `Shell command permission check failed for pattern`, in a slash command's `local-command-stderr` or in the result of a Skill call. Such a run used to read VALID because the skill-fired grader saw the call. The verdict now says "failed to load", not "did not fire". In an invocation-probe or `--measured-fire` case a failed Skill call only warns, since the call is what those cases measure.
- `/evals:validate` counts a pre-computed line the way Claude Code reads it: `` !`command` `` only at a line start or after whitespace, or a line opening a ```` ```! ```` block. It no longer warns on a `` ``!`command` `` `` mention in prose, which loads. It now reads tags from `case.yaml` as well as from `prompt.md`, and no longer keeps the trailing period of a prompt such as `/playbooks:skill-authoring.` in the skill name. The skill-authoring cases, whose skill failed to load in every run, used to get no warning because of those two misses.
