### Added

- The control-skill contract gains an "Environments" section. Environment entries (`url`, dependency `services`, `extends`, a `writes` policy per write of `never`, `attended` or `unattended`, and `production: true`) come only from `config/defaults.json` committed at HEAD. The local, environment-variable and flag layers may select an environment by name, never add or redefine one; the driver CLI refuses such a layer with exit 4. An entry that extends a production entry stays production.
- The contract gains an "Integrated apps" section: a system whose pages a journey crosses, such as a separate identity server, gets its own control skill, and its steps are included by reference as `<app>:<path>`. The `checkouts.<app>` setting holds the path of another repository's local checkout; when it is unset or wrong, the run stops before launching and names the setting and the repository to clone. Committed config pins each such app by commit SHA in `pins.<app>`; the run stops before launching, and again before each included `cli:` call, that app's launch and its Ready, unless the checkout holds that commit, its HEAD and its control skill folder match it byte for byte (no index flags, filter attributes, replace refs, fsmonitor or inherited `GIT_*` variables, no symlink out of the folder; CRLF is the only normalization) and the folder holds no untracked or ignored file other than its `config/local.json`; that app's config and floors are read at the pin. An unset pin tells the person to commit `pins.<app>`, for example through `/app-control:map`, which writes a pin only for a commit on the default branch of the hub line's repository URL. An included `cli:` step runs the owning app's `cli/` with that app's config, a minimal environment holding that app's credential variables (never the hub's own or a loader or interpreter variable), `--environment` set to the mapped environment (checked against its `--json`), and `--kind` set to the include's kind. An included step runs under the owning app's committed floors, enforced by its CLI; the including control skill can tighten it only through the include's `kind` or by leaving it out. A driver CLI writes nothing inside its control-skill folder, so the untracked-file check does not stop a second run, turns bytecode off itself, and loads code only from that folder plus dependencies pinned with integrity hashes by a lockfile there.
- A new Write grants floor: every write command takes `--step <id>`, the step's unprefixed id (or the command name without a steps file), unique across the control skill's own steps files and never equal to a `cli/` command name. The CLI binds the key to the step's `cli:` command at HEAD (or the command of that name), refuses a command whose non-reserved arguments differ, and applies the strictest committed grant among every key bound to that command; a missing or unknown id, an unlisted one, `never`, or `attended` without `--attended` exits 4. External systems take a `systems` entry per environment, committed only.
- `<environment url>` and `<<service> service url>` placeholders in Launch and Ready are filled as one argument, validated as an http(s) URL with no shell metacharacters, and run without a shell; a `.cmd` or `.bat` program is refused.
- `report.json`'s `launch` is a list with one entry per launched app, and cleanup stops each.
- The Production floor now states that `--yes` needs `--attended`, so no config turns on an unattended production write. Writes to environments not marked production keep their current rules.
- `## Capture` can hold one row per tier (such as browser and server). `/app-control:drive capture` records each tier's row with its own tool, and the tier is part of the artifact name.
- `/app-control:drive ready` checks each dependency service of the selected environment: that it answers, and, where the app shows its target, that the app sends to it. `report.json`'s `ready` gains `environment` and `services`.
- `/app-control:map create` asks for each related system's repository and for which environment is production. It writes environment entries and an Integrated apps hub line, and it never writes into another checkout.
