### Changed

- **Breaking:** `/docs-hygiene:compress` no longer runs `markdownlint-cli2` from `PATH` or `node_modules/.bin`, and no longer stops when it is absent. It finds your repository's own markdown lint command through the plugin's new copy of the ecosystem resolution steps (`reference/ecosystem-resolution.md`) and runs it scoped to each edited file, passing the file when the command lints only the paths it is given. It runs the same command once before the edit and blocks a ship only on a new failure of the file: one that names it, counted per file and rule, never matched by line number, or, when the file was passed to a command that lints only its arguments, any new failure message, named or not, or an exit status that was 0 before the edit and non-zero after it. `lint=PASS` means the edit added no new failure; a target that already failed before the edit is named as such. It runs only a command that reads: one that can write files (a `--fix` or `--write` flag, a fix or write option in the linter's config file, or a recorded `fix-cmd`) is never run, and the target reports `lint=unresolved`. Just before each lint run, the baseline included, it copies every target to a temporary file, deleted when the run ends, and before and after the run it records `git status --porcelain -uall` and the hashes of the files that output reports plus every target, recording a missing or non-regular path as absent; if any file changed, tracked or untracked, a target included, it restores each changed target from that copy, never runs the lint command again in that run, reports every target `lint=unresolved`, names the changed files and keeps compressing. A failure in another file no longer reverts a compression; a command it cannot scope passes every target when it exits 0 after the edit, and marks the target `lint=unresolved` when it fails without naming a file, unless the run before the edit exited 0, in which case it reverts the target and reports `lint=FAIL`. When none resolves, it skips the lint step, marks each target `lint=unresolved` and ships after every other check. The summary field is now `lint=PASS|FAIL|unresolved`, not `markdownlint=PASS|FAIL`. To keep the lint gate, record the command in `docs/conventions/ecosystems/<ecosystem>.yaml` (`/toolchain:setup apply <ecosystem>`), state it in your instructions, or declare it as a manifest script ([#17773](https://github.com/melodic-software/claude-code-plugins/issues/17773)).
- **`compress`, `audit-derivability` and `rename-references` no longer name tools from one ecosystem.** The code-file extension examples, the named cross-vendor advisor plugin, the `package.json` / `pyproject.toml` / `Cargo.toml` manifest examples in the container-mode ladder and Form 14, and the Python / C# / JS rename examples are gone; the rules now state them in general terms ([#17773](https://github.com/melodic-software/claude-code-plugins/issues/17773)).

### Removed

- **`/docs-hygiene:setup` no longer checks `markdownlint-cli2`.** It validates the `compress_articles` setting only ([#17773](https://github.com/melodic-software/claude-code-plugins/issues/17773)).
