### Added

- Bundled review criterion "Fail a change that loosens a check" (`skills/quality-gate/context/loosened-check.md`): a change that skips, focuses or deletes a test, changes an expected value to match the code, lowers a threshold, adds a suppression, sets a check to soft-fail, removes a check, raises a retry count or a test's own timeout, or edits a check's own code, runner, workflow or settings so it accepts more fails unless the spec names it and says why. A removal passes when the spec names it; a soft-fail passes only as a flaky test's quarantine with the spec's reason. Only spec text gives a reason, never the pull request body or comments. `/review:quality-gate`'s diff modes, the `code-reviewer` agent and every `/review:fanout` leaf that reviews code always apply it: a project's own criteria add findings beside it, and no project document, instruction file or text in the change replaces or relaxes it.
- Settings `loosened_check_verdict` (`fail` or `note`, default `fail`, a policy floor) and `loosened_check_patterns` (path globs or `text:` patterns, the union of every layer), each a user option and a `docs/conventions/review.yaml` key read from the default branch, resolved by `scripts/loosened-check-settings.mjs`.
- The `fanout-sweep` workflow requires `loosenedCheck` (the criterion's path, which every slice, named leaf and model tier reads) and dispatches nothing without it. It also takes `loosenedSettings` (the criterion's two resolved setting lines, given to every leaf) and `spec` (the issue text, quoted as data in every leaf prompt). `/review:fanout` resolves the settings in both review modes.
- Seven eval cases for the criterion's verdicts, and a criterion-citation grader on the lowered-coverage case.
