### Fixed

- With execution enabled (`disk_hygiene_enabled` on, the default), a scan-only `/disk-hygiene:clean` no longer locks the rest of the session out of `gh`, `git` and test commands. The skill's belt now denies only while a clean run is open, tracked by a per-session marker in a new engine-owned `clean-runs/` directory under the plugin data directory. A `preview` opens the run, which stays open until the run's `apply` or `handoff-apply` writes its report, or the preview ends in `manual-handoff-lane` or `blocked`; the engine deletes the marker at those ends. A `handoff-apply` with no preview holds the belt until its report lands, and each manual-lane `handoff-verify` holds it until an hour passes with no engine call. A `scan` alone opens no run. The marker fails closed: one the guard cannot parse holds the belt until the hour passes, and a payload with no session id keeps it on. The engine also deletes a marker past the hour on its next call; the guard never deletes one, and a later engine call cannot revive an ended or timed-out run. With the kill switch off (`disk_hygiene_enabled` false, audit-only mode) the lockout remains: once the skill loads, the belt never stands down, so Bash keeps its deny-by-default, `gh`, `git` and test commands included, and PowerShell deletion spellings stay denied for the rest of the session, run or no run. The engine gate, the approval token and the belt's verdicts during a run are unchanged; the residual that a session can backdate its own marker is recorded in the safety model.
