### Changed

- **Standing policy reads the config-cascade layers.** Without `--policy`, the clean engine layers the JSON file named by the new `policy_file` option (passed to the engine as `--user-policy`), then the project's `<home>/disk-hygiene.yaml` and `<home>/disk-hygiene.local.yaml`. `<home>` is the convention home the project's pointer region names, default `docs/conventions`. Only the `policy_file` file or an explicit `--policy` may set `elevation: uac-prompt` ([#18009](https://github.com/melodic-software/claude-code-plugins/issues/18009)).
- **`/disk-hygiene:setup` moves the old policy files.** `check` lists each old file and where it goes. `apply` previews the move and acts only after a yes. It writes the new file, sets `policy_file` through Claude Code's configure route, checks that the policy resolves the same, and then removes the old file through `/disk-hygiene:clean`'s gated apply, behind that skill's own confirmation. It never overwrites a new file that already exists.

### Deprecated

- **`~/.claude/disk-hygiene.json` and `<project>/.claude/disk-hygiene.json`.** Each is still read in place of its layer while no new file supplies that layer. Each scan prints one warning per old file, naming where it moves and `/disk-hygiene:setup apply`, and lists the warnings in the new `policy_warnings` output field. When the new file exists, the old one is not read and the warning names both. A later release stops reading them.
