### Changed

- The convention documents testing a lane change with `gh workflow run <workflow> --ref <branch>`, and what such a run does not exercise: the actions and scripts under `.base`, a lanes-token mint while the caller workflow differs from the default branch, and a dispatcher-sent pair.
- pr-review-main's fallback leg emits a warning annotation when the fallback token reviews a lane, and copies the loosened-check criterion beside the lane's skill.
- The eval workflows name each model id once; report-outcome adds any `pr_body_required_sections` section its PR body lacks; each lane workflow opens with a fixed summary block (lane, purpose, triggers, stage) that a test holds to `lane-rules.json` and the file's `on:` events.
