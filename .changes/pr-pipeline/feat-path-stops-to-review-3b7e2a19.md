### Changed

- A trusted path no longer stops a lane; the review lanes judge it. `CODEOWNERS` and `.gitmodules` leave every `patch-rules.json` row and `UNIVERSAL_REFUSE`, and `.gitmodules` leaves `prepare.sh`'s conflict refusal. Address-feedback's thread scope is path hygiene alone (`thread-scope.mjs`: a plain path in normal form), so `CONTROL_PATH`, the instruction-file list and the plugin and `pr_paths` scope rules are gone from the select job, `apply-patch.mjs`'s `kept-threads` rule, the reply job and the review-thread tool; a PR that changes `.github/workflows/` no longer escalates `feedback-protected-path`.
- A kept path (a workflow, a `settings*.json`, an agent instruction file the review CLI loads from the head (`CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `.claude/`, `.mcp.json`, `.lsp.json`: the new `agent-instructions` refusal), a `.gitattributes` (the new `gitattributes` refusal), a symbolic link, a gitlink, a backslash path, a rename into one) no longer refuses a `[head]` patch whole: `apply-patch.mjs` withholds it, pushes the rest, and writes the withheld part as `kept.diff` with its SHA-256. The write runner uploads it as `kept-paths-<lane>-<activity>-<attempt>`, and its `kept-paths` job posts it in one `<!-- lane-kept-paths -->` comment edited in place, naming the head, the SHA-256 and the run (`.github/scripts/apply-patch/kept-paths.mjs`). The row's `max-files`, `allow` and `content-rule` now see every change, kept ones included (the content rule skips a symbolic link or gitlink, which its own refusal keeps), so a narrow row (`dependency-review`, `review-threads`) never hands on a withheld change it would not admit. `prepare.sh` escalates a conflict on any path `apply-patch.mjs` refuses. A PR patch of kept paths alone skips `prerequisite-missing`; an issue one comments that the apply is pending, adds no human label and removes `agent-ready`.
- `collect-patch.sh` leaves a CLI scrub-stub name that holds content out of the patch and names it on stderr, instead of writing no patch.
