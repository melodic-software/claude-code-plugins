### Changed

- The pr-merge lane (`babysit_merge.py --unattended --authority pr-merge`) treats every pull request the lanes App opened, with exactly one closing issue in this repository and no denied path, as class C2 and reads no `work-class:` label or label history; the risk score's diff-derived C2 checks still apply. With a rung above off it refuses `verifier-verdict-not-required` unless `merge.require-verifier-verdict` is true, since the pr-verify verdict is now its merge criterion. `recheck_lane_class` becomes `recheck_lane_issue`: right before the enqueue the closing issue must still be the one the eligibility read found (`closing-issue-changed:<was>><now>` otherwise), and a removed class label no longer refuses. Dependabot pull requests are unchanged and need no verdict. The closing issue must carry the owner's ratification marker (`find_ratification`, a port of resolve-config's `ratification.mjs` that `tests/test_ratification_sync.py` checks against it), read fresh from its comments and the trusted-actor list at the base, at eligibility and again before the enqueue; otherwise `not-ratified`, and a failed read refuses.

- The pr-merge lane reads three new `merge.diff-check` switches, each off when absent: `high-path-floor` (the risk scorer's fixed HIGH path set), `c2-contradictions` (a removed, renamed or copied file, a schema change, or more than one plugin) and `max-changed-files`; there an absent `max-changed-lines` is no cap and an empty `denied-paths` no longer refuses `denied-paths-unset`. A switch value other than true or false turns it on, and a cap that is not a count holds the rung at off. `babysit_risk.RiskInput` gains `high_floor`, `c2_contradictions`, `max_changed_files` and `lines_optional`, whose defaults keep every check, so the local babysit lane is unchanged.
