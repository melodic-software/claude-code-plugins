### Changed

- `/work-items:morning-brief` resolves where its status page goes through the shared medium resolver (`lib/view-settings.mjs`, lane `work-items:morning-brief`) and prints the resolver's report line naming the medium and what decided it ([#12701](https://github.com/melodic-software/claude-code-plugins/issues/12701)).

  The settings are a medium named in the request, the new `medium` option, the team file `docs/conventions/rendered-views.yaml` and the personal override `docs/conventions/rendered-views.local.yaml`. A team file can keep the page local but never publishes it.

### Added

- `medium` plugin option: where `/work-items:morning-brief`'s status page goes (default `auto`, a local file).

  It is work-items' first option picked from a fixed list, so the plugin now needs Claude Code v2.1.271 or later.

### Removed

- `/work-items:morning-brief` no longer publishes on a value from `~/.claude/rendered-views.md`, `.claude/rendered-views.md` or `.claude/rendered-views.local.md`

  These files are retired. A `terminal` or `file` value in one still keeps the page local when no other setting gives a medium; an `artifact` or `hosted` value is ignored. Each gives one notice naming its value and where to set it instead. `/work-items:triage` still reads them until its own change.
