### Added

- `docpage-digest-batch` workflow ([#7369](https://github.com/melodic-software/claude-code-plugins/issues/7369)): digests several documentation pages with every Phase 3 digest agent, both Phase 4 verifier arms and each correction round dispatched by the workflow script, so no agent has to spawn another and no page skips verification. `/knowledge:docpage-digest` documents it as its Batch path and `/knowledge:map-corpus` launches it for a multi-page queue. Its stages run as the new `knowledge:digest-worker` agent.
- The workflow rejects a page URL that is not https on a public host, or that carries a quote, `$`, a backtick, whitespace or another shell metacharacter, before any agent sees it, and applies the same checks to the post-redirect canonical URL; it returns rejected and deferred pages with a reason each and a `verification` of `unverified: not run: <reason>`, which map-corpus records. The single-page path runs the same checks on the canonical URL before any shell command carries it. A profile's model mapping reaches a prompt only as `opus`, `sonnet`, `haiku` or a `claude-<family>-<version>` model ID, and a unit key from a verifier finding only inside a data fence. Verifier B runs as a same-vendor refuter, recorded degraded in its header, because `codex:codex-rescue` returns raw stdout that cannot carry a structured verdict. A verifier reply outside the verdict set or finding severities leaves the page `unverified: verifier <A|B> returned an off-schema reply`, and a page an earlier run marked verified is verified again by this run. A flag a stage returns (`pinned`, a gate's `pass`, `applied`, `written`, `phase3Done`) counts only as the boolean `true`, and a correction agent starts only for a unit the page's setup returned.
- The checklist gains a `Verification status` line (`verified`, `unverified: <reason>`, `failed: <reason>`), copied into the interview handoff's first line and each map-corpus `queue.json` entry.
