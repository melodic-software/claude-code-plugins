### Changed

- The generate and unattended `evals.json` files are retired into the `evals/` case suite ([#8635](https://github.com/melodic-software/claude-code-plugins/issues/8635)). Of the eleven legacy cases, three were already covered: the stage-table case by `gen-stage-table-first`, the approval-gate case by `gen-approval-gate`, and the dashboard routing case by `una-routes-2fa`. The other eight become seven new cases: `gen-env-visibility-honest` (the .env is read for key names only, and the reply says honestly what reaches the model), `gen-library-off-limits` (the library above the STAGES marker stays unchanged when the user asks to trim `ask()` and allow http in `open_url`), `gen-gh-absent-degrades` (a missing gh only warns and adds closing-summary entries), `una-author-elevated` (an elevated host setup routes to unattended and is authored from the template with `Assert-Elevation -Mode Required`), `una-wsl-retire-guarded` (the two WSL cases merged: host-side guard, UTF-8 listing, parsed-state check, declared irreversible step last, verified afterwards), `una-guarded-drain` (a failed proof keeps the pool held) and `una-preview-explained` (`-WhatIf` for the human, `-Test` only after approval, and a dry run is no proof of the end state). `gen-stage-table-first` gains a grader that the key is marked secret and the sender ID is not. `gen-approval-gate` gains graders for the `bash -n` check and the fresh-context subagent trace. The legacy expectation that the user is asked only what the files leave open is dropped, because no grader can tell which questions the files left open. So is a check that each row says how the person gets the value: the console in these cases is fictional, so the skill's rule makes that cell `unverified` or a question, and a check for a page, menu or button would reward invented steps. The generate cases that grant Bash are tagged `no-network`, since the skill may try to read vendor documentation. Both `evals.json` files are deleted.
