### Changed

- The generate and unattended `evals.json` files are retired into the `evals/` case suite ([#8635](https://github.com/melodic-software/claude-code-plugins/issues/8635)). Of the eleven legacy cases, three were already covered: the stage-table case by `gen-stage-table-first`, the approval-gate case by `gen-approval-gate`, and the dashboard routing case by `una-routes-2fa`. Four more become new cases: `gen-env-visibility-honest` (the .env is read for key names only, and the reply says honestly what reaches the model), `gen-library-off-limits` (the library above the STAGES marker stays unchanged when the user asks to trim `ask()` and allow http in `open_url`), `gen-gh-absent-degrades` (a missing gh only warns and adds closing-summary entries) and `una-preview-explained` (`-WhatIf` for the human, `-Test` only after approval, and a dry run is no proof of the end state). The remaining four, the elevated authoring case, the two WSL cases and the guarded drain, are tracked on #8635: the eval's permission check denies the skill's Bash copy of `template.ps1` out of the plugin directory, so they cannot run there yet. `gen-stage-table-first` gains a grader that the key is marked secret and the sender ID is not. `gen-approval-gate` gains graders for the `bash -n` check and the fresh-context subagent trace. The legacy expectation that the user is asked only what the files leave open is dropped, because no grader can tell which questions the files left open. So is a check that each row says how the person gets the value: the console in these cases is fictional, so the skill's rule makes that cell `unverified` or a question, and a check for a page, menu or button would reward invented steps. The generate cases that grant Bash are tagged `no-network`, since the skill may try to read vendor documentation. Both `evals.json` files are deleted.
