# Re-normalization — the 15 rows the first normalization pass missed

The merge-time normalization claimed 21 rows and covered 13. These 15 INLINE-ONLY rows — 6 from
[`audit/B03.md`](../audit/B03.md), 9 from [`audit/B08.md`](../audit/B08.md) — were never tested
against the criteria as they now read in
[`LEDGER.md`](../LEDGER.md) "Audit criteria".

All 15 `SKILL.md` files read in full, plus `plugins/re-anchor/context/re-anchor-audit-correct.md`
(the shared four-step method every corrector runs). Three criteria changes drive the re-test:

1. **The two-part interaction test.** Needing user input is not itself a blocker; a blocker stated
   as "needs `AskUserQuestion`" is the defeasible tool-shaped form the criteria reject. Restated as
   the absence of a USER, then tested for *mid-flow load-bearing* or *gates an irreversible action*.
2. **A start-of-run gate is pre-dispatch parent work**, not a blocker.
3. **`history-fork` is a fourth mechanism** — `subagent_type: "fork"`, the only one inheriting the
   live transcript. The transcript leg of every re-anchor blocker is void under it.

**Result: 12 confirms, 3 flips.** Line references are to each skill's own `SKILL.md` unless noted.
