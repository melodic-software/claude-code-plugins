## Notable

- **Adjudicated: `allowed-tools` in these three skills is *not* the checklist's hard blocker.**
  Three rows carry `allowed-tools` — `playwright` (`SKILL.md:8`, `Bash(playwright-cli:*)`),
  `explore-directions` (`:7`) and `pressure-test` (`:7`) (both `git branch` / `git status` /
  `head` / `echo` / `detect-ecosystems.sh`). The checklist names "permission grants via
  `allowed-tools`" parenthetically under the blocker *"turn-scoped state the parent must observe
  live"*. Read against the category head rather than the example, none of these three binds:
  nothing about a `playwright-cli` or `git status` allowlist is state the **parent** must observe
  live. The grant is pre-authorization that suppresses prompts for those commands; the commands
  themselves run under whatever `Bash` permission the dispatched agent inherits from the parent.
  The grant here is ergonomic, not contractual — so all three stay DISPATCH-OPTIONAL rather than
  flipping to INLINE-ONLY. The residual question is only whether the ergonomics survive a `skills:`
  preload (an implementation caveat, recorded per-row), not whether dispatch is permissible.
  **`allowed-tools` is common across the marketplace — this adjudication should be applied fleet-
  wide or the eleven batches will resolve it inconsistently.**
- **The right unit of dispatch is frequently a *phase* of a skill, not the whole skill.** This is
  the load-bearing lesson from the reference implementation and the actual basis for all three
  DISPATCH-OPTIONAL calls in this batch: `plugin-quality:audit` dispatches step 2 (map+ground)
  while steps 4 (contract-lock interview) and 6 (egress confirm) stay on the main thread because
  they need the user; `explore-directions` should dispatch variant generation but never the
  flip-and-pick loop; `pressure-test` should dispatch the build but never the hand-drive loop;
  `playwright` should dispatch a full E2E run but never turn-by-turn driving. The Brief's Decision
  1 frames dispatch as a whole-skill posture ("`/research` and `/explore` **dispatch a subagent by
  default**"). For the 138-skill sweep that framing is too coarse — a large class of skills is
  neither DISPATCH-DEFAULT nor INLINE-ONLY but "dispatch this phase, keep that one", and the
  verdict vocabulary currently has no cell for it. DISPATCH-OPTIONAL is the closest fit and is
  being stretched to carry it.
- **Frontmatter check — no existing dispatch declarations anywhere in this batch.** None of the
  eight carries `context: fork`, an `agent:` field, `model:`, or `background:`. The only
  frontmatter that changes a verdict is `/playbooks:update`'s `disable-model-invocation: true`
  (next bullet); the other seven are all `disable-model-invocation: false`.
- **`disable-model-invocation: true` is a mechanism blocker, not just a triggering preference.**
  `/playbooks:update` is this batch's instance. Per the Brief's constraint block, `skills:` preload
  requires the target to keep `disable-model-invocation: false`, so any such skill can only ever be
  reached by a dispatched agent through an explicit `Skill` tool call — if at all. Worth a
  fleet-wide sweep for other `true` values before the mechanism is generalized.
- **Phase-0 corpus enumeration (Decision 6) — applicable, not currently triggered.** `boris` is a
  genuinely bounded corpus (107 tips / 95 sections / 8 files) and `fable-5` is another (13
  chapters). Neither skill today claims exhaustive coverage — both are one-question-one-file
  navigation hubs, so there is nothing for a coverage ledger to enforce. The discipline *would*
  bind the moment either grows a whole-corpus mode (a "check my setup against every tip" sweep, or
  `fable-5 full` used as an audit rather than an arming step). Record as deferred with that trigger
  rather than as not-applicable.
- **Index-plus-sidecar (Decision 4) — already the house style on the read side, but without the
  machine-readable header.** Four of eight skills in this batch are already hub-plus-spoke with an
  explicit routing table: `boris` (Topic Index → `reference/`, 1308 lines behind it), `fable-5`
  (chapter-routing trigger table → `context/`, 1363 lines), `playwright` ("Progressive disclosure
  map" → `reference/`, 1109 lines), `plugin-quality:audit` ("Reference index — load on demand",
  and `SKILL.md:208-209` "Never grow this hub; push depth into references"). What none of them
  have is Decision 4's *machine-readable sidecar header* — `reference/foundations.md` opens with a
  plain `# Foundations (Sections 1–15)` and prose subtitle, so a consumer can only grep the hub's
  table, never the sidecar itself. That gap is the concrete delta between existing practice and
  the Brief's target shape, and these four hubs are the best in-repo exemplars to copy the routing
  table from.
- **`fable-5`'s `context/orchestration.md` is a first-principles competitor to this audit's own
  criteria.** It fixes delegation to exactly three task shapes (fan-out of 5+ independent items,
  context-flooding side work, isolation-as-the-product) with four *stay-inline conditions that
  override all three* — sequential steps consuming each other's output, files under active edit,
  jobs under ~5 tool calls, and "you will need the full detail later in the session". The
  checklist's DISPATCH-DEFAULT signals and that chapter's triggers are not in conflict, but the
  stay-inline overrides are sharper than anything the checklist currently encodes and are the
  reason three skills in this batch land on DISPATCH-OPTIONAL rather than DISPATCH-DEFAULT. Worth
  reconciling the two lists deliberately rather than letting them drift.

## Reference implementation — `plugin-quality:auditor`

Source: `plugins/plugin-quality/agents/auditor.md` (59 lines), dispatched from
`plugins/plugin-quality/skills/audit/SKILL.md` step 2.

**Frontmatter shape — minimal.** Exactly three fields: `name`, `description`, and
`tools: "Read, Grep, Glob, WebFetch, Bash, Write"` (a quoted comma-separated string, not a YAML
list). No `hooks`, `mcpServers`, or `permissionMode` — consistent with the Brief's acceptance
criterion that plugin agents must not declare fields the harness ignores for them. Also absent:
`model`, `background`, `isolation`, `maxTurns`, `memory`, `initialPrompt`. Every declared tool
survives both harness filters, so the agent is background-safe by construction rather than by
luck.

**It does NOT use `skills:`.** The discipline is authored inline in the agent body instead: the
untrusted-content posture (`auditor.md:21-26`) and the fresh-docs grounding rule
(`auditor.md:37-41`) are restated in the agent, duplicating text that also lives in the
dispatching skill (`SKILL.md:20-23`, `SKILL.md:120-128`). This is the pattern's one clear
weakness and a direct argument for Decision 2's `skills:` preload: the current shape is two copies
of one rule in two files that must be kept in sync — a pointer-not-copy violation and a live drift
risk. It is *not* the "prose discipline reminder" the Brief rejected, though: the discipline
arrives as content, not as recall. Treat it as a third mechanism point on the spectrum —
inline-authored discipline — that `skills:` preload strictly dominates.

**Context passing is by path, not by paste.** The dispatch prompt carries three things only: the
evidence-packet path, the target `<plugin>[:<component>]`, and the component-type lens *file
paths* to apply (`SKILL.md:120-124`). The agent's step 1 is to read the packet off disk
(`auditor.md:29-31`). Nothing bulky crosses the dispatch boundary in either direction.

**The return contract is exactly Decision 1 and 4's shape.** The agent writes `findings.md` into
the packet directory and returns a summary — "finding count by severity, the top findings in one
line each, and the packet path" (`auditor.md:52-59`) — and the skill's zone table consumes it that
way, with the dumb/unknown rows forbidding a bulk re-read (`SKILL.md:81-82`). The parent decides
per-stage whether to open the artifact at all. This is the pointer-plus-summary contract already
running in production in this marketplace.

**Two further transferable lessons.** (1) The agent carries an explicit *tool-honesty note*
(`auditor.md:15-19`) declaring why it holds non-read-only tools and bounding `Write` to exactly
one destination — the evidence packet. A dispatched `discovery:researcher`/`explorer` writing into
`.work/<slug>/` should carry the same bounded-write declaration. (2) The dispatching skill
specifies *fresh context, never a fork* — "A fork would inherit this session's degraded history —
the fresh-eyes doctrine is the point" (`SKILL.md:127-128`) — which is independent corroboration of
Decision 2's rejection of `context: fork`, on a different ground (evidence hygiene) than the
Brief's (no per-invocation prompt, silent narrow-tool-set trap).

## Method note

Verdicts went through one independent-reviewer pass after the first draft. It carried three
corrections, all applied: the `allowed-tools` adjudication was promoted from a per-row caveat to
an explicit Notable ruling (it would otherwise have flipped three rows to INLINE-ONLY on a strict
reading of the checklist's parenthetical); the phase-vs-whole-skill observation was added; the
`/plugin-quality:audit` Mechanism cell was de-scoped so a mechanical merge does not read it as a
dispatch verdict.

Rationale cells run longer than the checklist's one-to-two sentences because each carries its
file+line evidence. A compressed form will be needed when these merge into the 138-row ledger.
