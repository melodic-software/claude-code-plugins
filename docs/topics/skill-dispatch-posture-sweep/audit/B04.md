## Notable

- **Skill-load-time machinery is unverified under `skills:` preload, and it gates the plugin-agent
  mechanism marketplace-wide.** PLAN.md establishes that `skills:` preloads skill *content*; it says
  nothing about whether the following execute or apply inside a subagent. Three kinds appear in this
  batch alone: `!` pre-computed context blocks (`teach` line 55, `firecrawl` line 13, `update` line
  13), `allowed-tools:` grants (`firecrawl`, `update`), and `${user_config.…}` substitution
  (`quiz-me`'s `quiz_policy`/`report_library_dir`, and `offer_browser_automation` in both `github`
  skills). If precompute does not run under preload, a preloaded `firecrawl` agent starts without its
  CLI status line; if `${user_config.…}` does not substitute, `quiz-me` sees a literal placeholder and
  falls back to its unset behavior. Worth verifying empirically before the mechanism is locked.
- **Per-skill verdicts are too coarse for three rows.** `simulation --discover-bcs` (mechanical,
  reproducible, table-producing), `methodology --<format>` (pure reference read), and `update --check`
  (report-only) are all dispatchable sub-actions sitting inside INLINE-ONLY skills. Whichever way the
  sweep resolves this, multi-action skills need an action-level granularity decision, not a single
  per-skill posture.
- **Decision 4 (index-plus-sidecars) is not universal — one skill's contract forbids it.**
  `quiz-me`'s report is deliberately self-contained with "durable pointers only": "Never link
  memory-tier paths (`.work/…`) or contract-slice paths (`docs/topics/…`) — both are pruned or
  checkout-local and will dangle." A sidecar set is exactly the shape that contract rejects. Meanwhile
  `github:audit` — the batch's one DISPATCH-DEFAULT — has no artifact at all yet, so the progressive
  disclosure requirement lands as new work rather than a reshape.
