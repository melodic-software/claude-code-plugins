## Notable

- **This batch is the marketplace's dispatch *consumers*, not its dispatch candidates.** Four of the
  eleven already mandate fresh-context subagent dispatch as part of their own contract
  (`audit-answers` Step 2, `devils-advocate` Fresh-context requirement, `plan` Steps 3 and 4, plus
  `plan` Step 4.5's per-phase execution-surface routing table). The dispatch-posture question for
  planning is less "should this skill move off-thread" and more "are the units it already dispatches
  named plugin agents or anonymous general-purpose ones."
- **A recursion trap sits under `audit-answers` and `plan`.** Both are INLINE-ONLY partly *because*
  they must spawn subagents, and `Agent` is stripped from every subagent unless
  `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` is set — which Decision 3 deliberately keeps optional. Any
  sweep that dispatches a skill which itself dispatches silently degrades that skill's mandatory
  fresh-context step to inline self-critique. `plan`'s Step 3 is labelled "MANDATORY — never skip"
  and its Gotchas repeat it (L336); a silent degradation there defeats the skill's central control.
- **`AskUserQuestion` is guarded, not assumed, across this plugin.** `design`, `plan`, and `prd` all
  gate it behind a `use_ask_user_question` user config that defaults **off**, falling back to inline
  numbered prose. So the harness constraint "AskUserQuestion is unavailable in subagents" is not what
  actually blocks these skills — prose rounds are equally unreachable from a subagent, because the
  blocker is *the absence of a user*, not the absence of a tool. Worth stating that way in the sweep's
  conclusions, or the INLINE-ONLY justifications will look defeasible ("just turn the config off").
- **`design`'s artifact set is an existing progressive-disclosure precedent.** `capability-matrix.md`
  / `type-inventory.md` / `library-topology.md` / `design-threads.md` is already an index-plus-sidecars
  shape with a per-scope artifact table (L158–168), and `design-handoff` reads exactly one of them to
  gate. Decision 4's index-plus-sidecars requirement for `RESEARCH.md`/`EXPLORE.md` has a working
  in-repo model to copy rather than invent.
- **Progressive-disclosure gap:** `devils-advocate` is the only DISPATCH-DEFAULT in the batch and it
  persists nothing at all — its Risk Summary and per-severity findings live only in the conversation.
  Dispatching it without adding an artifact would *lose* the findings, not relocate them.

## Splittable phases

Ordered by value. Each is a sub-phase of an INLINE-ONLY skill that could dispatch independently while
the dialogue stays on the main thread.

1. **`/planning:wayfind` — the non-interactive `work` frontier (highest value in this batch).** The
   skill already computes exactly the dispatchable set: `frontier = open ∧ zero OPEN blockers ∧
   unassigned`, and "In a non-interactive session, further filter OUT `needs-human` items" (L106–110).
   Mode is materialized as a single label at charting time — "HITL types (`interview`, `design`,
   `prototype`) get the `needs-human` label; `research` omits it (autonomous-capable)" (L94–96) — and
   `wayfind: research` items route to `/discovery:research`, itself becoming dispatch-default under
   this effort. So `wayfind work --autonomous` over the non-`needs-human` frontier is dispatchable
   *wholesale*, with `chart` and every HITL item staying inline. The label already encodes the seam;
   nothing new has to be invented. Caveat: the claim protocol (`@me` assignee + claim-comment lease,
   L112) and the graduation sequence (comment → index → close, L123–126) are tracker writes a
   dispatched agent would perform under the parent's identity — the parent must own the choice to let
   it write.
2. **`/planning:interview` — Step 1 Survey, and per-question fact resolution.** Step 1 is a pure
   grounding pass (read `CLAUDE.md`/`AGENTS.md`, Glob/Grep keywords, `git log --oneline -20`, climb to
   the nearest domain-vocabulary file, inspect the topic's contract and memory slices, L141) whose
   product is one paragraph — a textbook many-files-in / one-paragraph-out dispatch. The skill already
   asks for the second half: "When a fact lookup is slow (deep exploration, external research),
   dispatch it to a sub-agent and DON'T block the round" (L113). Formalizing both as a
   `planning:interview-surveyor` agent keeps every round inline while the codebase reading happens
   off-thread. Same shape applies verbatim to `/planning:prd` Step 2 (L84–93).
3. **`/planning:brainstorm` — Steps 2–3 (ground + diverge).** "fast breadth pass (`Glob`/`Grep`/targeted
   Read — survey the file landscape before reading anything in depth) over where the problem lives"
   feeding "~10 candidates … Every candidate is codebase-grounded — names the files/mechanisms it
   would touch — one line each" (L20–21). The dispatched agent returns exactly the candidate list; the
   Step 4 reaction and Step 5 calibrate-and-route stay inline. This is the cleanest producer/consumer
   split in the batch: the returned artifact IS the reaction surface, so nothing is lost in
   summarization.
4. **`/planning:plan` — Step 2's standards grounding, and Steps 3/4 as *named* agents.** The
   "Ground in consumer standards" pass (resolve the index, match surfaces, pull only matched sections,
   L78–88) is read-heavy with a citation list as its product. Steps 3 and 4 already dispatch; the
   change is naming them (`planning:plan-reviewer` preloading `context/plan-reviewer.md`,
   `planning:stress-tester` preloading `devils-advocate`) instead of handing a general-purpose agent a
   prose brief. Step 4.7's outcome gate is *deterministic* (`grep -c "Sanity Check" PLAN.md` ≥ phase
   count, status-tag presence, L198–205) — that is script work, not agent work, and should be a script
   the parent runs.
5. **`/planning:prd` — the `review` action.** "Locate the topic's `PRD.md` … Evaluate against the seven
   required sections … Check goals are *outcomes*, not implementations … Present findings" (L190–197):
   an artifact-in / findings-out audit with no user dialogue in the loop. Dispatchable as-is. The
   sibling `synthesize` action is explicitly **not** splittable — it consumes conversation context a
   subagent cannot see (L113).
6. **`/planning:design` — the `terminology` action and the `status` report.** `terminology` is a
   cross-cutting naming review of the full type inventory against project conventions, library-name
   collisions, and domain vocabulary (L142–152) — read-heavy, findings-shaped, with only the final
   glossary sync needing the user. `status` is read-only over existing artifacts (L58, and artifact
   creation is explicitly skipped for it, L68). Both dispatch while the discussion rounds stay inline.
7. **`/planning:audit-answers` — Step 2's validators as named agents.** Already dispatched (1–3
   fresh-context, non-fork, each seeing the whole answer set, rationale withheld, L49–51). A named
   `planning:answer-validator` with a `skills:` preload of `devils-advocate` would replace today's
   reuse-by-prose-reference ("That discipline is **reused by reference, not restated here**", L53),
   which is exactly Decision 2's "discipline arrives as recall, not content" objection.
