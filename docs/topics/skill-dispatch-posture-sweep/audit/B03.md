## Notable

### 1. `!` pre-computed context blocks under `skills:` preload — unresolved, and load-bearing for Decision 2

Nine of my twelve skills open with a `## Pre-computed context` block using `!`-shell injection (the
three without are `clean`, `audit-encapsulation`, and `extract-ssot`).
Decision 2's mechanism preloads skill content into a subagent via `skills:` frontmatter, but neither
the Brief nor the checklist says whether preload *executes* those injections or ships the literal
text. Material cases in this batch:

- `/discovery:explore` loses branch, working-tree status, and **project root** — and its own outcome
  gate has a criterion written against that root (*"no finding in the artifact echoes an absolute
  machine path (notably the pre-computed project root)"*). The gate cites a value that may not exist
  in the dispatched context.
- `/docs-hygiene:audit-noise` loses its `detect.sh` findings sample, which its action router then
  expects to map to the tier table.
- `/discovery:blindspot`, `/discovery:explore-deep`, `/discovery:research`,
  `/discovery:research-deep`, `/docs-hygiene:audit-derivability`, `/docs-hygiene:compress`, and
  `/docs-hygiene:rename-references` all carry the same shape.

This wants an empirical check before the `discovery:explorer` / `discovery:researcher` agents are
written; it is not answerable from the Brief.

### 2. `explore-deep` empirically confirms the rationale for rejecting `context: fork`

Decision 2 rejects `context: fork` partly for its *"silent narrow-tool-set trap."* `explore-deep` is
that trap, in the tree, today:

- Line 24 asserts *"You inherit the parent's full toolset"* — false. Per the Brief's constraint, a
  `context: fork` skill is a regular agent type receiving the narrow background tool set unless it
  sets `background: false`; only the `fork` *subagent type* inherits the parent's exact pool.
- Its frontmatter description attaches `CLAUDE_CODE_FORK_SUBAGENT=1` as a hard requirement
  (*"requires CLAUDE_CODE_FORK_SUBAGENT=1 — when unset, fall back to inline `/explore`"*), and
  `/discovery:explore` line 24 repeats it. That env var gates the `fork` subagent type, not
  `context: fork` frontmatter — the requirement is attached to the wrong mechanism.

Both claims are wrong in the same direction (they overstate the fork's capability), so the skill
reads as safer than it is. Worth fixing regardless of how the USER-RESERVED deferred question about
the `-deep` variants resolves.

### 3. Nested-spawn degradation is **not** graceful for fresh-context verification disciplines

Decision 3 treats `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` as an optional detected capability whose
absence means *"slower, same coverage."* That holds for research breadth, where sequential execution
substitutes for parallel fan-out. It does **not** hold for two skills in this batch:

- `/docs-hygiene:audit-derivability` requires the deletion spot-test to run in *"a **fresh-context,
  non-fork subagent**… that has NOT seen the document"*, and names the reason: *"The self-grade
  trap."*
- `/docs-hygiene:compress` requires the semantic diff to run as *"a SEPARATE fresh-context audit,
  never a self-audit by the model that produced the edits"*, with an observed failure rate
  (*"4/4 reverse-direction edits in one batch compression wave"*).

Both need a *different, uncontaminated* context — not more wall-clock. A dispatched agent that has
already read the document cannot substitute for the verifier by running longer. So for these
skills the env var is a hard prerequisite for dispatch, not an optimization, which contradicts
Decision 3's "graceful degradation" framing. This is the highest-value cross-cutting finding in the
batch.

### 4. `/discovery:explore` — Brief-vs-text inconsistencies

- **Routing section (lines 18-26)** presents three co-equal options with inline as the structured
  default; Decision 1 makes dispatch the default and inline the documented escape hatch. Needs
  rewriting, not just amending.
- **Line 36, plan-mode paragraph** — *"switch into plan mode for harness-level read-only
  protection."* `EnterPlanMode`/`ExitPlanMode` are dropped in every subagent, so this is
  inapplicable in a dispatched run and needs scoping to the inline escape hatch.
- **Output-format item 7** — *"**Surface these to the USER**, each with a one-line recommended
  default"* and *"Silent downstream resolution of surfaced open questions is an anti-pattern."*
  The Brief already anticipates this (acceptance criterion: the parent re-surfaces), but the skill
  text still addresses the user directly and needs to name the parent as the re-surfacing party.
- **Coverage-ledger asymmetry (line 26)** — *"write a numbered gap-list before any deepen pass."*
  The Brief's constraint says any coverage ledger a dispatched agent maintains must be a file on
  disk, since `TaskCreate`/`TaskUpdate`/`TaskList`/`TaskGet` do not survive the background filter.
  Decision 5 creates `research-checklist.md` for `research/SKILL.md` only; `/explore` gets no
  equivalent despite an identical constraint and an identical ledger. **This is a gap in the Brief,
  not in the skill.**
- **Line 154** — the ~2000-word overflow threshold contradicts Decision 4.

### 5. `/discovery:research` — Brief-vs-text inconsistencies

- **Line 148 self-contradicts under dispatch-by-default** — *"Subagent returns are Tier 3
  (synthesis), not corroborators, until their cited primaries are fetched this turn."* Once dispatch
  is the default, the main conversation's entire view of the research **is** a subagent return, and
  therefore Tier 3 by the skill's own rule. Decision 1 accepts the bounded summarization loss
  (*"the full artifact is on disk and the parent may read it on demand"*), but the sentence as
  written reads as forbidding the new default. It needs amending to distinguish the *artifact* —
  which carries the URLs captured that turn — from a *return read in place of* the artifact.
- **Line 65** — *"**Prefer direct-context web** (WebSearch / WebFetch **in the main session**) for
  the highest-value queries — results land without summarization loss."* `WebSearch`/`WebFetch`
  survive the background filter, so the capability is intact, but the "in the main session"
  instruction directly opposes Decision 1 and must be rewritten.
- **Line 126** — *"prefer direct research when results inform decisions"* is already named in
  Decision 1 as deliberately overridden; recorded for completeness only.
- **Line 174** — the ~2000-word overflow threshold contradicts Decision 4.
- Decisions 5 and 6 (mandatory coverage discipline, Phase 0 corpus enumeration,
  `research-checklist.md`) have no counterpart in the current text — expected, since they are new
  work, not drift.

### 6. Six of twelve are INLINE-ONLY, and five of the six say so themselves

`research-deep`, `compress`, `rename-references`, `extract-ssot`, and `clean` each name their own
blocker in their own text — a workflow-tool requirement, a mandatory fresh-context verifier, an
`AskUserQuestion` confirm phase, a per-phase human diff review, a per-tier approval gate. Only
`blindspot` required deriving the blocker from its contract rather than reading a stated one. That
suggests the sweep's INLINE-ONLY set can largely be found by grepping for `AskUserQuestion`,
`Workflow`, and "fresh-context" across the remaining 126 skills before reading them in full.
