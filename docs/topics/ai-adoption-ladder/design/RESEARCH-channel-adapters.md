# RESEARCH — Channel / data-feed trigger landscape for AI coding agents (mid-2026)

## Task

Map, vendor-agnostically, how AI coding-agent products get triggered from **communication channels** (Slack, Microsoft Teams, Discord) and **continuous data feeds** (alerts, analytics, monitoring streams), and derive what a vendor-neutral "channel / data-feed adapter" contract must abstract over. Primary-source-first per `/discovery:research` discipline (fetch official docs, flag every unverified claim, recency-gate). Feeds a product-agnostic contract design — vendor names are evidence, not vocabulary. Seven coverage areas: Claude Tag, Cursor, OpenAI Codex, GitHub Copilot coding agent, Google Jules, generic bot/relay frameworks, continuous data-feed monitoring.

## Summary

Across every vendor the trigger surface converges on **four recurring shapes wearing different names**: a **mention-trigger** (`@bot <prompt>` in a chat thread — universal: Claude Tag, Cursor, Codex, Copilot), an **assignment-trigger** (assign a tracker issue to the agent, or a triage rule that does so — Codex/Cursor in Linear & Jira, Copilot via GitHub issue, Jules via `jules` label), a **channel-monitor / ambient-trigger** (the agent proactively watches a channel and acts unprompted — today essentially only Anthropic's Claude Tag "ambient mode"), and a **feed/event-trigger** (a schedule, webhook, or external event like a PagerDuty incident or failed build starts a run — Cursor Automations, Jules API, and every generic webhook relay). The load-bearing distinction the task asks for — **true push vs. scheduled polling** — cuts cleanly: chat mentions and monitoring webhooks (Slack Events API, MS Graph change notifications, Datadog/PagerDuty outbound webhooks, Cursor's webhook/PagerDuty triggers) are **push** (the source calls you); "watch a feed every N minutes" and cron "heartbeat" patterns are **poll**; Microsoft Graph is a distinct **push-with-lifecycle** model (subscriptions expire and must be renewed, and require a validation handshake). The **entitlement floor** is stark: every *native* vendor integration is plan-gated (Claude Tag = Enterprise/Team beta; Codex = Plus/Pro/Business/Enterprise/Edu; Copilot = any paid plan + admin policy for Business/Enterprise; Cursor = usage-based billing account), while the **universal free floor is the DIY path** — a chat platform's own bot primitives (Slack Events API `app_mention` + bot token, or a Teams bot / Graph subscription) or a plain inbound webhook, wired by you to whichever agent runner you own.

## Conflicts

- **"Webhook" is an overloaded word across surfaces — resolved by direction, not the label.** A Datadog/PagerDuty "webhook" is the *feed pushing outbound to you*; a Cursor Automations "webhook trigger" is *an inbound endpoint you POST to*; a Slack "webhook" (Events API endpoint) is *Slack pushing to you*; a Graph "webhook" is *push-with-lifecycle*. No factual contradiction — the same word names opposite ends of the same pipe. The adapter contract must model **direction + lifecycle**, never trust the word "webhook."
- **Copilot Teams provenance.** One WebSearch hit (community discussion #177494) is a *feature request*, which would be weak evidence; but the falsification pass found an **official changelog (2025-09-19) + an official docs page**, so Teams support is confirmed shipped (public preview), not aspirational (row 8). The Slack docs page genuinely does not mention Teams — that is page scoping, not absence of the feature.
- **Codex docs host migration.** `developers.openai.com/codex/*` now 308-redirects to `learn.chatgpt.com/docs/*` (same live move noted in the sibling headless-agents research). Cite the redirect target.

## Synthesis — trigger concepts, adapter contract, entitlement floor

### (a) Common trigger concepts across vendors (one concept, many names)

| Neutral concept | What fires it | Push/Poll | Seen as (vendor names) |
|---|---|---|---|
| **Mention-trigger** | `@bot <prompt>` in a channel/thread | Push | Claude Tag `@Claude`, Cursor `@cursor`, Codex `@Codex`, Copilot `@GitHub` (Slack+Teams) |
| **Assignment-trigger** | Assign a tracker issue to the agent (or a triage rule that does) | Push (tracker webhook) | Codex-in-Linear (assign / triage rule), Cursor-in-Jira (assign `@Cursor`), Copilot (assign GitHub issue), Jules (`jules` label) |
| **Channel-monitor / ambient-trigger** | Agent watches a channel and acts unprompted | Push (subscription) | Claude Tag "ambient mode" (only first-party instance found); DIY via Slack Events API / MS Graph tenant/channel subscription |
| **Feed / event-trigger** | External event: incident, failed build, alert, merged PR | Push | Cursor Automations (PagerDuty, GitHub PR, webhook), Jules API ("failed webhook"), Datadog/PagerDuty outbound webhooks |
| **Schedule-trigger** | Cron / interval; often a "heartbeat" the agent reacts to by checking state | Poll | Cursor Automations (cron), `jules-action` schedule, generic scheduler |

### (b) What a vendor-neutral channel/data-feed adapter contract must abstract over

Interrogating every surface above against the five task dimensions yields the contract:

1. **Auth / installation** — abstract over: OAuth app install + bot token (Slack), Graph app registration + delegated/application permissions + subscription (Teams), tracker OAuth (Linear/Jira/GitHub), per-vendor plan entitlement gating (§c), and a bare inbound-webhook secret. Contract surface: `install(channel_type, credentials) → connection_handle`; must carry scope/permission metadata so the runner knows what it may read.
2. **Event subscription vs. poll** — a **first-class enum on the adapter**, not an implementation detail: `PUSH` (register endpoint / Socket Mode / Graph subscription), `PUSH_WITH_LIFECYCLE` (Graph — must schedule renewal before `expirationDateTime`, handle validation-token handshake), `POLL` (interval + cursor/state). The adapter owns subscription renewal and the 3-second-ack / validation-handshake obligations so the runner never sees them.
3. **Signal payload → normalized work item** — every surface delivers a different envelope (Slack event JSON, Graph `resourceData` [maybe encrypted], Datadog templated JSON, tracker issue payload). Normalize to one **WorkItem**: `{ intent/prompt, source_ref (channel+thread+message id | issue id | alert id), actor, repo/context hint, raw_payload }`. Mention/assignment carry an explicit prompt; feed/schedule triggers carry *state to inspect*, so the WorkItem must distinguish **imperative** (do this) from **observational** (something changed — go look).
4. **Provenance capture** — persist origin for audit and idempotency: which channel/tracker/feed, which message/issue/incident id, which actor, which subscription, delivery timestamp, and a **dedupe key** (Slack retries, Datadog retries, Graph redeliveries all mean at-least-once delivery — the adapter must be idempotent). This is also the raw material for the "monitor by exception" story in the sibling ladder research.
5. **Threading / reply-back** — a `reply(source_ref, status|result)` capability that maps back to the origin thread: post to the Slack/Teams thread, comment on the Linear/Jira issue Activity, update the GitHub PR/thread. Abstract the common lifecycle every vendor exhibits — **ack (👀 / "on it") → progress → result+artifact link (usually a PR)** — so the runner emits neutral lifecycle events and the adapter renders them per channel.

### (c) Entitlement gating vs. the free/universal floor

**Plan-gated native surfaces (paid, per vendor):**

- **Claude Tag** — Enterprise/Team **only**, beta.
- **Codex** — Plus/Pro/Business/Enterprise/Edu (+ GitHub connection + environment).
- **Copilot coding agent** — any **paid** Copilot plan; Business/Enterprise need an **admin policy** enabled; caller needs repo **write access**.
- **Cursor** — Cursor account with **usage-based pricing** enabled.
- **Jules** — API is alpha; task/day + concurrency caps (per sibling: 60/day, 5 concurrent).

**Universal free floor (no vendor coding-agent license):** the chat platform's own primitives + your own runner.

- **Slack:** free Slack app + **Events API `app_mention` + bot token** (Socket Mode needs no public URL) → your `claude -p` / Agent SDK / any runner. This is the true floor.
- **Teams:** a Teams bot **or** a **Graph change-notification subscription** (app registration + permissions; handle renewal + validation). Higher setup cost than Slack, same "no coding-agent license" property.
- **Discord:** DIY only (Gateway/Interactions + bot token) — no native vendor surface found (Gap #1).
- **Data feeds:** any monitoring tool's **outbound webhook** (Datadog `@webhook-`, PagerDuty, CI failed-build hook) → your endpoint → runner. Push, free, universal.
- **Generic relay:** a plain **inbound webhook + shared secret** is the lowest-common-denominator adapter both above the chat floor and above the feed floor.

**Net floor statement:** the free, vendor-agnostic path to "signal in a channel/feed → agent run" is always **{platform bot primitive OR inbound webhook} + {your own agent runner}**; the paid native integrations buy you managed install, threading, and hosted execution, but abstract to the *same four trigger concepts* — so an adapter built to the §b contract can drive either the free floor or a licensed native surface behind one interface.
