# RESEARCH — Headless / autonomous coding-agent landscape & issue-queue lifecycle (mid-2026)

## Task

Map the headless / non-interactive autonomous coding-agent landscape as of mid-2026 across three clusters — (1) Anthropic surface, (2) competitor surface (OpenAI Codex, Cursor, GitHub Copilot, Google Jules, xAI Grok), (3) issue-queue-driven autonomous lifecycle patterns without a human in the loop — and synthesize toward Boris Cherny's adoption-ladder transitions (2→3, 3→4) and what a repo-agnostic, tool-agnostic autonomous-runner framework must abstract over. Produced by the `/discovery:research` discipline (3+ phases, primary-source-first, mandatory falsification, recency gate). Broad-topic (6 vendors) → doubled minimums applied.

## Summary

By mid-2026 every major vendor ships a **converging two-tier headless shape**: (a) a **local CLI print/exec mode** for pipeline embedding (`claude -p`, `codex exec`, `grok -p`) that runs the full agent loop, prints a result to stdout, and exits; and (b) a **cloud "assign-and-forget" surface** (Claude Code on the web, Codex cloud, Cursor cloud agents, GitHub Copilot cloud agent, Google Jules) that clones the repo into an ephemeral isolated VM, works on a branch, runs tests, and opens a PR. Issue-queue invocation is real and standardized on GitHub primitives: **label or assignment → agent → draft PR**. The critical nuance the falsification step surfaced: the hosted issue-to-PR agents **deliberately keep a human review gate** (Copilot cannot mark its own PR ready-for-review, cannot approve/merge, and its Actions workflows require human approval to run); a **fully closed, no-human loop is achievable only on the self-operated CLI/SDK surfaces** where you own the isolation and the merge policy. That distinction is exactly the boundary between Cherny's ladder rungs.

## Synthesis — ladder mapping & framework abstraction

**Mapping to the (verifiable) Cherny ladder.** Cherny's citable framing is the abstraction ladder *code → agents-write-code → agents-prompt-agents*. Rendered as the brief's adoption transitions:

- **2→3 "let Claude kick off Claude."** The enabling primitives now all exist first-party: Agent SDK **Subagents** (`AgentDefinition`) and background subagents/workflows in `claude -p` (row 1–2); Cursor "kick off and manage more agents in parallel"; Codex/Cursor/Jules parallel cloud tasks. This rung is **agent-orchestrates-agent**, still human-initiated per task.
- **3→4 "loop fully closed, monitor by exception."** Here the vendor landscape **bifurcates**, and that is the load-bearing finding: the **hosted issue-to-PR agents keep a human merge gate by design** (row 12) — so out-of-the-box they sit at "closed *authoring* loop, human-gated *merge* loop." A **truly closed loop** (issue → PR → merge → next, no human) requires the **self-operated CLI/SDK surfaces** where you own isolation + branch-protection bypass + merge policy (Ralph's `while` loop, row 16; Agent SDK + Managed Agents; Copilot only if added as a branch-protection bypass actor / skip-approval opt-in). "Monitor by exception" therefore = you run your own outcome gate and only surface failures.

**What a repo-agnostic, tool-agnostic runner must abstract over** (Claude/Codex/Cursor/Copilot/Jules/Grok):

1. **Invocation adapter** — normalize the local-CLI shape (`claude -p` / `codex exec` / `grok -p`, differing flags, output formats: all three offer a `stream-json`/`--json` variant) vs. the cloud-API shape (Codex cloud, Cursor, Jules API, Copilot via GH API).
2. **Structured-output contract** — every tool emits machine-readable JSON (`--output-format json`/`--json`), but schemas differ; abstract a common result envelope (result text, session id, cost, exit status).
3. **Queue + lease** — GAP #2: the runner must own this. Convention shape: an *agent-ready* label as the queue, atomic assignment/lock as the lease (one agent per issue), one-branch/one-PR-per-task (Copilot's model) as the anti-double-work invariant.
4. **Isolation policy** — ephemeral VM/container, default-deny egress + allowlist, secret scoping, filesystem block on `.env`. Vendors implement this differently (bubblewrap/seatbelt, GH Actions runner + firewall, managed VM); the runner abstracts *policy*, delegates *enforcement*.
5. **Outcome-verification gate** — build/test must pass before PR (Ralph "tests as backpressure"; Jules runs the suite; Cursor self-tests). Tool-agnostic gate = exit-code + CI status, not agent self-report.
6. **Merge policy / human-gate toggle** — the 3→4 knob: fully-closed (self-run, bypass actor) vs. human-review-required (hosted default). Must be explicit per repo.
7. **Observability + cost** — capture `stream-json` transcripts, per-invocation `total_cost_usd` (Claude) / Codex cost, session ids; monitor-by-exception alerting on gate failures.
8. **Session/resume + cost caps** — resume semantics (`--resume`, `codex exec resume`, SDK sessions) and per-run/per-day caps (Jules 60/day-5-concurrent is the reference shape).
