## T1 — INDEX.md frontmatter schema (design-it-twice) — status: resolved (Sketch A)

The Brief locks: frontmatter is the single home for child order + slice
status, preserved across regeneration. Contested: the key shape.

**Sketch A — minimal, list-as-order (recommended):**

```yaml
---
slice: identity-migration
abstract: "One-line abstract of this slice — the parent index mirrors it verbatim"
status: active        # active | parked | done
children:             # ordered; this list IS the curated order
  - current-state
  - target-design
---
```

The `abstract` key is this slice's single-home one-liner: the PARENT's
generated body mirrors it verbatim (T3's source for a child that is
itself a slice; an index-less leaf's abstract comes from its sole
artifact's header instead). The `children` list doubles as ordering and
as the parity baseline under the child-slice predicate defined in T5: a
child-slice directory on disk absent from the list (or vice versa) is an
orphan the gate flags. No other per-child metadata here; per-child facts
stay at the child (single-home).

**Sketch B — rich child rows:**

```yaml
children:
  - slug: current-state
    kind: slice
    status: done
  - slug: target-design
    kind: slice
    status: active
---
```

Carries per-child status/kind at the parent. Rejected-leaning: duplicates
facts whose home is the child (violates single-home; every child edit
ripples to the parent frontmatter, exactly the maintenance tax the
research warned about).

**Sketch C — no frontmatter, sibling `slice.yaml`:**

State fully outside the index; INDEX.md becomes 100% generated. Cleanest
regen story, but two files where one serves, and the read-first binding
would need to name two files. Rejected-leaning.

## T2 — marker syntax + regen contract — status: resolved (revised per design verifier)

Markers reuse the repo's LIVE generated-region convention (two production
generators + hygiene tooling already key on it; a third shape reproduced a
recorded detector-miss failure):
`<!-- BEGIN GENERATED: slice index — regenerated by the shared lib script; edits inside are lost -->`
/ `<!-- END GENERATED: slice index -->`. The regen script rewrites only
between markers and never touches frontmatter. Exit codes are distinct
per failure class: missing/duplicated markers = exit 2 (ungradeable
shape); size cap = exit 3 (see T4); success = 0; parity mismatch = 1.
Only the orchestrating session invokes regen.

## T3 — child-header mini-schema (what regen parses) — status: resolved (revised per design verifier)

Generalize the sidecar-header precedent: every indexable artifact opens
with a YAML header carrying at minimum `abstract:`. **The abstract is ONE
unwrapped line, always** (MD013 is off so length is free): the repo's
always-on markdown formatter was empirically shown to rewrite a wrapped
continuation line starting with `+` into a `-` list marker, silently
corrupting verbatim-copied text — so wrapped abstracts are forbidden in
headers AND in the generated body, and the regen tests carry a
`+`-leading-continuation regression case. A child slice's abstract is its
own INDEX.md frontmatter `abstract`; an index-less leaf's abstract is its
sole artifact's header abstract, where **the sole artifact resolves by an
ordered precedence over the reserved names** (INDEX.md > EXPLORE.md >
RESEARCH.md > INTENT.md > PLAN.md > PRD.md > SOURCES.md; two or more
present means the leaf has multiple artifact families and therefore
REQUIRES an index — no tie-break needed). Corollary shipped in the same
wave: the EXPLORE/RESEARCH/INTENT index files gain a YAML frontmatter
block (`abstract:` at minimum) in discovery's artifact-shape spec — today
only the sidecars carry headers, and a discovery slice is exactly the
index-less leaf whose abstract must come from its index artifact. The
mini-schema is versioned in the contract README and parsed by the shared
lib script only; the dispatch gate stays header-blind (see T5) so no
plugin hand-parses it.

## T4 — size-cap behavior — status: resolved (option a, revised per design verifier)

Brief: ~25KB expectation, deliberately tightened here to a halt (the Brief
left the behavior contested; the README states the tightening). At the
cap the regen script exits 3 (distinct code, see T2) with a two-lever
hint: decompose the slice, or shorten abstracts (the cap is driven by
abstract length × child count — the T3 mini-schema's one-line rule is the
second lever). **Cap-fail never destroys navigation:** any pre-existing
generated body is left intact and the failure says so, so a
post-fan-out-join slice with children is never left index-less (the state
T9's read-first binding cannot resolve). Never silent truncation.

## T5 — dispatch-gate candidate rule (design-it-twice) — status: resolved (Sketch A)

**Sketch A — exact assignment, no scan (recommended):** the gate takes the
exact slice path the parent assigned (it already resolves one pre-dispatch)
and grades only that path. The collision escape stops being a scan radius:
on collision the PARENT assigns the sub-slice before dispatch and passes
that path. The entire ambiguity class (two candidate indexes → exit 2)
disappears because the gate never searches. **Two revisions per the
design verifier:** (1) The explore collision escape is worker-side TODAY
(explorer discovers occupancy and picks the sub-slice itself; research is
already parent-assigned) — the same wave moves it parent-side: the parent
stats the slice root pre-dispatch and assigns the collision sub-slice in
the envelope (edits: explore SKILL.md's collision rule, the explorer
agent body's collision instruction and payload template, and
artifact-shape.md's worker-reports-the-path licence). (2) Orphan parity
does NOT live in this gate — the gate stays header-blind by its own
design doctrine; parity is a check the shared lib regen script performs
(it owns the mini-schema), comparing the frontmatter `children` list
against on-disk CHILD-SLICE directories, both directions, exit 1 on
mismatch; a slice with no INDEX.md reports parity `not-applicable`
explicitly (a skipped check must never look passed). Flip PR also
rewrites the two research SKILL sentences that describe the retired
post-synthesis exit-2 ambiguity semantics. **Child-slice predicate
(deterministic, content-derived):** a
subdirectory counts as a child slice iff its root contains `INDEX.md` or
any reserved UPPERCASE index artifact (`EXPLORE.md`, `RESEARCH.md`,
`INTENT.md`, `PLAN.md`, `PRD.md`, `SOURCES.md`); every other
subdirectory (`design/`, `baselines/`, `scratch/`, `verification/`,
`resources/`, `claims/`, and anything else) is slice-interior under the
interior-freedom clause and exempt from parity. This keeps the two-way
check from false-orphaning sanctioned noun folders and existing layouts.

**Sketch B — retained scan, tightened:** keep root-plus-one scanning but
require the payload pointer to disambiguate when two candidates exist.
Preserves today's worker-side collision autonomy; keeps the ambiguity
failure mode alive and adds a payload-trust dependency the gate was built
to avoid. Rejected-leaning.

## T8 — depth-proof worktree carry — status: resolved

Replace the depth-enumerated globs with reserved-name-keyed recursive
patterns (gitignore syntax; both the native copy and worktree-create.sh's
`git ls-files --exclude-from` reimplementation honor `**`):

```text
.work/.gitignore
.work/**/INDEX.md
.work/**/EXPLORE.md
.work/**/EXPLORE-*.md
.work/**/RESEARCH.md
.work/**/RESEARCH-*.md
.work/**/INTENT.md
.work/**/INTENT-*.md
.work/**/*-checklist.md
```

This is the last recipe migration consumers ever need: new depths require
no pattern change. Baselines and raw scratch stay uncarried (machine-bound).

Two verifier-added notes for the flip: the `**` semantics are verified
empirically for the ls-files reimplementation only — the README claim
about the NATIVE mechanism is stated as ".gitignore syntax, including
`**`" without asserting a verification that was not performed. And since
the knowledge seam shape-unifies to INDEX.md under a `.work` root,
`.work/**/INDEX.md` will carry corpus-slice indexes into spawned
worktrees; the README notes that corpus-heavy consumers may add their own
exclusion lines to their consumer-owned `.worktreeinclude`.
