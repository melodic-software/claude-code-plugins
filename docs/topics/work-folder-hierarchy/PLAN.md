# work-folder-hierarchy

## Brief

### TLDR

Redesign the `.work` memory-tier convention as topic-docs contract v3: a recursive
slice tree with one reserved `INDEX.md` per slice (frontmatter state + generated
body), index-declared ordering, lifecycle states, and the knowledge corpus seam
kept but shape-unified — shipped as one clean-break major wave, substrate PRs
first.

### Goal

A uniform, shipped-by-default working-folder convention where the tree tells the
story at every depth: simple work stays one file, decomposed work grows child
slices, every slice is navigable through one index read, and corpus-scale
ingestion never overflows a topic slice.

### Decisions (locked 2026-09-01, validated by two fresh-context validators + a
stress-test; evidence in `.work/work-folder-hierarchy/`)

1. **Recursive slice tree.** A slice is the same thing at every depth; an "epic"
   is a slice with child slices. A new level is created lazily — on decomposition
   or on collision — never pre-built. Recursion is scoped to topic slices:
   concern dirs (`handoffs/`, `reviews/`, `running-retros/`, `exports/`,
   `overengineering/`) keep their session/branch axes; claude-ops lanes gets a
   reserved concern home in the wave. Activities (explore/research/plan/ledgers)
   share their unit-of-work's slice and never create levels.
2. **`INDEX.md` reserved per slice.** Frontmatter is the single home for child
   ordering and slice status (`active | parked | done`), preserved across
   regeneration; a marker-delimited body (child list + verbatim abstracts copied
   from child artifact headers) is regenerated by a shared `lib/` script. Only
   the orchestrating session regenerates; fan-out workers never write above
   their assigned slice. Hard size expectation ~25KB. "Read INDEX.md first"
   becomes a normative contract binding, not just a file shape.
3. **Ordering is index-declared only**, scoped to child-slice directory names.
   Never numeric prefixes on slice names; timestamped concern filenames and
   sanctioned interior ordinals (e.g. `digests/NN-*.md`) are unaffected.
4. **Name collision resolved by rename.** docpage-digest's `INDEX.md`
   (source-inventory semantics) is renamed in the same wave with its
   resume/parity references updated; an interior-freedom clause states that
   slice-shape rules govern slice placement and reserved names, never
   slice-interior files.
5. **Corpora stay in the knowledge `library_dir` seam**, shape-unified to the
   same slice/INDEX.md conventions inside it; topic slices hold pointers. Two
   roots, one documented relationship.
6. **Promotion posture unchanged; hygiene fixed.** `contract_tier: branch`
   remains the shipped default. The 11 stale `docs/topics/` slices on main are
   cleaned and the existing prune gate's coverage audited — no new gate is
   built (`scripts/check-contract-slice-prune.sh` already exists and is wired).
7. **One clean-break major wave** (documented versioning precedent). Substrate
   PRs land first (lib regen script + tests, reworked dispatch gate),
   unreferenced; one normative flip PR last (README v3 + schema + all bindings
   + artifact-protocol copies + setup skills + CHANGELOG major entry).

### Constraints

- Guard invariants hold: memory writes never picked up by a governing checkout;
  no plugin modifies tracked content; consumer root `.gitignore` never edited.
- Single-home rule: indexes reference (verbatim-copied abstracts), never restate.
- ~19 plugin surfaces fetch the contract README by raw URL at runtime — nothing
  partial reaches main; the wave merges once.
- Depth-coupled surfaces move in the same wave:
  `plugins/discovery/scripts/check-dispatch-artifact.sh` (grade the exact
  assigned slice path; keep the one-level collision escape; add the
  orphan-child parity direction), the `.worktreeinclude` recipe (depth-proof
  `**` patterns keyed on reserved names; add `INTENT*.md` and `INDEX.md`),
  `plugins/source-control/scripts/worktree-create.sh` (reimplements the carry),
  docs-hygiene exemption roster, map-corpus's hard-bound line.
- Windows/portability floor: colon-free timestamps, reserved base names,
  bash-parsable header mini-schema owned by the contract; regen-script copies
  registered in `scripts/cross-plugin-source-registry.txt` from day one.
- Slug/scratch schemes are blessed-or-absorbed per axis (topic, branch-slug,
  constant, content-hashed; `scratch/` dir vs `scratch-` prefix) — plan-level
  detail, no scheme silently retired.
- `done` + same-slug re-derivation = disambiguate, never resume. Tidy discipline
  owns slice-level lifecycle only; producer scratch rules unchanged. No always-on
  freshness hook (hook-budget rule).

### Acceptance criteria

- topic-docs README v3 + schema define: lazy level creation, INDEX.md reservation
  with read-first binding, frontmatter-state/generated-body split, ordering
  scope, interior-freedom clause, corpus-seam relationship, lanes' reserved home.
- Shared regen script + tests exist, registered, synced into every writer plugin.
- Dispatch gate grades the exact assigned path and the orphan-parity direction;
  existing collision escape retained; discovery/research dispatch flows pass.
- Worktree carry is depth-proof in both the native recipe and worktree-create.sh;
  INTENT and INDEX artifacts reach spawned worktrees.
- docpage-digest renamed file passes its own parity eval; no INDEX.md ambiguity.
- Main carries zero stale contract slices; prune-gate coverage audit recorded.
- Every implementer binding + the five artifact-protocol copies updated in the
  flip PR; drift checks green; one CHANGELOG major entry.

### Captured assumptions

- docpage-digest's renamed file is `SOURCES.md` unless planning finds a conflict.
- ~25KB index size expectation follows the cross-vendor cap signal (research D6,
  HIGH); exact number tunable at plan time.
- External research: five HIGH cross-vendor findings back planks 1–4; the corpus
  seam (plank 5) rests on in-repo judgment — accepted knowingly.
