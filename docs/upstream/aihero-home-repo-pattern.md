# Upstream source: AI Hero, "The Home Repo Pattern" (Matt Pocock)

This page records what this repository takes from, adapts, already has, or rejects in
[The Home Repo Pattern](https://www.aihero.dev/the-home-repo-pattern) (no license found, ideas
only), together with its companion
[video](https://www.youtube.com/watch?v=hWe-j78vNpc) and the author's two posts announcing it
([first](https://x.com/mattpocockuk/status/2120260969750540327),
[second](https://x.com/mattpocockuk/status/2120838662254420341)). Rows hold our decisions and our
own descriptions of each idea, under the upstream-drift convention's
[What a row may describe](https://github.com/melodic-software/claude-code-plugins/blob/main/docs/contracts/upstream-drift/README.md#what-a-row-may-describe).
The repository owner set every disposition on 2026-11-12; this record states them. The decision
itself is recorded in the organization's private architecture repository.

The estate this record speaks for is wider than this repository: the marketplace here, the
owner's user-scope dotfiles, the standards sync, and the organization's custom properties. A row
names the surface in this repository where one exists and says so when the owner is elsewhere.

- **Pointer**: when a row's idea needs its upstream wording, fetch

  linked above. The page has no stable section anchors, so each row names the section it comes

| ["Navigation pointers": a generated list](https://www.aihero.dev/the-home-repo-pattern) | Our own variant of the row above: a file listing every repository, written by the script that clones them | Not in the source. **Inference** | The same need as the row above | **reject:** considered and dropped on 2026-11-12. The clone script runs only by hand, so the file would lag the properties, and a file written into a checkout that does not yet ignore it stops that checkout from updating |
| ["Does the agent clone the repos, or use the copies already on disk?"](https://www.aihero.dev/the-home-repo-pattern) | The agent uses a sibling where the pointer says it is and clones it when absent; a variant nests ignored clones inside the hub | A pointer must work on a machine that lacks the clone. **Inference** | Getting every repository onto every machine | **already have:** one sync command per machine clones and fast-forwards every repository of both owners; agents never bulk-clone. Nested clones are rejected: we do not rely on a target repository's configuration loading from a directory that is only added to a session ([what an added directory loads](https://code.claude.com/docs/en/permissions#additional-directories-grant-file-access-not-configuration)) |
| ["Where do sessions start?"](https://www.aihero.dev/the-home-repo-pattern) | Sessions open in the hub, including the questioning round for a cross-repo feature | The hub is where the whole picture is visible. **Stated** ([source](https://www.aihero.dev/the-home-repo-pattern)) | A hub start changes what auto mode treats as in scope, and a target repository's hooks and project settings do not load from the hub | **adapt:** cross-repo sessions start in the hub and reach a target two ways: a subagent in a worktree of the target for small work, or a background session started in the target's worktree when its hooks and settings must load. Permission rules change only after a behavior probe (`plugins/harness-ops/skills/behavior-probes/SKILL.md`) and a repeat in the real setup show a change is needed, each one decided by the owner |
| ["How do worktrees fit in?"](https://www.aihero.dev/the-home-repo-pattern) | Each repository has one clone and each feature a worktree of it | Several agents can then work in one repository at once. **Stated** ([source](https://www.aihero.dev/the-home-repo-pattern)) | Parallel sessions in one repository | **already have:** `/source-control:worktree`, which places worktrees outside the clone (`plugins/source-control/skills/worktree/SKILL.md:98`) and guards them with a session claim |
| ["Where do issues go?"](https://www.aihero.dev/the-home-repo-pattern) | The agent files each issue in whichever repository it fits | It can read every tracker, so it can sort them. **Stated** ([source](https://www.aihero.dev/the-home-repo-pattern)) | Work that no single repository owns had nowhere to be filed | **adapt:** an item goes in the hub's tracker only when no single repository owns it; otherwise in the owning repository, with links. Items about the owner's personal-account repositories are linked, never copied. Hub items are worked by hand; anything a lane can do is filed where the lanes run |
| ["Can a team share a Home Repo?" and "Why a repo, and not `~/.claude/skills`?"](https://www.aihero.dev/the-home-repo-pattern) | The hub is the shared, versioned thing a team runs agents in, in place of each person's user folder | A user folder is unversioned and invisible to teammates. **Stated** ([source](https://www.aihero.dev/the-home-repo-pattern)) | The objection assumes an unversioned user folder | **already have:** the user-scope files here are rendered from a versioned repository and reviewed by pull request, so the objection does not apply to a solo operator. | ["How many repos does it handle?": one file per area](https://www.aihero.dev/the-home-repo-pattern) | Past a few dozen repositories the pointer list splits into per-area files that the main file names | A long flat list is too many choices for the agent. **Stated** ([source](https://www.aihero.dev/the-home-repo-pattern)) | About two dozen repositories, already grouped by a `system` property | **reject:** no list is kept (rows above); the grouping it would give is the `system` property |
| ["How many repos does it handle?": a marketplace at large scale](https://www.aihero.dev/the-home-repo-pattern) | At very large repository counts, skills move to a marketplace | Many consumers of the same skills. **Stated** ([source](https://www.aihero.dev/the-home-repo-pattern)) | Skill distribution | **already have:** the marketplace is the distribution route at any size here |
