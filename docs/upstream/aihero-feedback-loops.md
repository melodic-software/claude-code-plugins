# Upstream source: AI Hero Cohort 005, Workshop 6 "Feedback Loops" (Matt Pocock)

This page records what this repository takes from, adapts, already has, or rejects in the
**Feedback Loops** workshop of Matt Pocock's AI Hero cohort (Cohort 005): nine lessons on giving an
agent ways to find out it is wrong. The workshop splits that feedback in two: deterministic checks
that fail on bad code, and data sources that tell the agent what its environment is doing. It
prunes a written standards file into checks, places and speeds up those checks, writes a custom
lint rule, grades tests with mutation testing, and gives a diagnosis skill and a browser the data
it needs. Our counterparts are [`/corrections:codify`](../../plugins/corrections/skills/codify/SKILL.md),
[`/debugging:debug`](../../plugins/debugging/skills/debug/SKILL.md),
[`/mutation-testing:audit`](../../plugins/mutation-testing/skills/audit/SKILL.md),
[`/testing:test-value`](../../plugins/testing/skills/test-value/SKILL.md),
[`/implementation:implement`](../../plugins/implementation/skills/implement/SKILL.md),
[`/app-control:drive`](../../plugins/app-control/skills/drive/SKILL.md) and the check-placement
rules in [ADR 0072](../adr/0072-place-each-check-by-coverage-cost-and-model-facing-output.md).
Rows hold our decisions and our own descriptions of each idea, under the upstream-drift
convention's [What a row may describe](../contracts/upstream-drift/README.md#what-a-row-may-describe).
The course is paid and account-gated, so no lesson text is recorded or linked here; the skills it
teaches are public and versioned in [mattpocock/skills](https://github.com/mattpocock/skills),
whose record is [mattpocock-skills.md](mattpocock-skills.md). Earlier course units have their own
records: [aihero-course.md](aihero-course.md), [aihero-shipping-course.md](aihero-shipping-course.md),
[aihero-domain-language.md](aihero-domain-language.md), [aihero-wayfinder.md](aihero-wayfinder.md),
[aihero-review.md](aihero-review.md) and [aihero-codebase-design.md](aihero-codebase-design.md).

- **Pointer**: when a row needs the upstream mechanism, fetch the public skill it rests on live:
  [`diagnosing-bugs`](https://github.com/mattpocock/skills/tree/4ae2317ddb22b046e26455e4f9c9b3aaaf62212d/skills/engineering/diagnosing-bugs).

### Making bad code nearly impossible

| Idea | What it does | Upstream problem | Our problem | Disposition | Landed |

### Pruning a coding-standards file

| Idea | What it does | Upstream problem | Our problem | Disposition | Landed |
|---|---|---|---|---|---|
| Each written rule is deleted, kept for judgment, or turned into a check | Moves mechanical rules out of prose | Inference: a reviewer agent may miss a written rule that a check never misses | Our instruction auditors could keep, as prose, a rule a check already enforces | **adapt**: `/harness-config:audit-instructions` flags instruction prose that a deterministic check already enforces | [#16615](https://github.com/melodic-software/claude-code-plugins/pull/16615) |
| Run the pruning pass over one standards file | Sorts a file's rules one by one | Inference: a standards file collects rules no one revisits | The pass needs an owner, and a retrospective reads sessions, not files | **adapt**: a `rules <file>...` action on `/corrections:codify` takes any instruction file (agent instructions, rules, review criteria), since choosing a rung per rule is codify's job | [#16633](https://github.com/melodic-software/claude-code-plugins/pull/16633) |
| Confirm the pruning dropped nothing | Checks the result against the input by hand | Inference: a rewrite can lose a rule silently | Same | **take**: the `rules` action keeps a ledger with one row per input rule, and its reconciler fails when a rule is missing | [#16633](https://github.com/melodic-software/claude-code-plugins/pull/16633) |
| Count today's violations for each proposed check | Shows what turning a check on costs | Inference: a check that fails everywhere at once is ignored | Same | **already have**: a codify proposal states the existing violations and offers a cleanup or a ratchet ([aihero-review.md](aihero-review.md), "Learning from review") | none |
| Many checks from one audit | Proposes a batch of checks from one file | Inference: a standards file is a backlog of checks | Our rule was one check per observed failure, never in bulk | **adapt**: a file of rules is a record of past corrections, so a batch from one file is allowed; each rule still gets its own check and its own fail-old, pass-new proof. A rule no commit ever broke is proved against a planted violation: `prove-check.sh --plant` commits it in a throwaway worktree that is never pushed and is removed on exit | [#16633](https://github.com/melodic-software/claude-code-plugins/pull/16633), [#16930](https://github.com/melodic-software/claude-code-plugins/pull/16930) |
| Style rules a formatter can enforce | n/a (raised while absorbing) | n/a | The enforcement ladder had no formatter rung, so a style rule could only become a lint check | **adapt**: the ladder gains a `formatter` rung: a style rule the repository's recorded format command (`fix-cmd` in its ecosystem record) can enforce routes there, and the `rules` ledger labels each style rule `formatter` or `lint`. The rule inventory cannot yet report the formatter rung: [#16931](https://github.com/melodic-software/claude-code-plugins/issues/16931) | [#16930](https://github.com/melodic-software/claude-code-plugins/pull/16930) |
| A skill used for its reference material, not its steps | Borrows a skill's checklist without running its procedure | Inference: useful guidance sits behind a procedure that does not fit | Reference files that assume the skill's steps cannot be reused | **take**: a skill's reference files must be usable without its steps; recorded in `/playbooks:skill-authoring` | [#16612](https://github.com/melodic-software/claude-code-plugins/pull/16612) |
| Hand session output to a later session through a secret gist | Stores a hand-off outside the repository | Inference: a session's findings need a home the next session can read | A gist is tied to one user account, and GitHub documents that anyone with a secret gist's URL can see it ([Creating gists](https://docs.github.com/en/get-started/writing-on-github/editing-and-sharing-content-with-gists/creating-gists)) | **reject**: hand-offs stay in the gitignored `.work/` folder or the tracker | none |

### First automated checks

| Idea | What it does | Upstream problem | Our problem | Disposition | Landed |
|---|---|---|---|---|---|
| Run checks at commit time, not on every agent edit | Keeps per-edit hooks out of the loop | Inference: a check per edit is slow and noisy and fires on half-written files | Same | **already have**: ADR 0072 places each check by cost and keeps report-only findings away from the model per edit; an audit of every shipped hook against it found none to move | none |
| A pre-commit hook on staged files only | Checks only what the commit holds | Inference: old violations should not block an unrelated commit | We could not see what each git hook stage runs, or how long it takes | **adapt**: the shared git-hooks installer gains a read-only `inspect` that lists every hook per stage, from plugins and elsewhere, and times only the plugin's own entries; it never runs a repository hook, a lefthook job or a Husky.Net task, since running one could change files | [#16627](https://github.com/melodic-software/claude-code-plugins/pull/16627) |
| A time budget for the commit hook | Keeps the hook fast enough not to annoy | Inference: a slow hook gets skipped | ADR 0072 named a commit budget but had not measured one | **adapt**: each git hook gets a 3 s budget, the course instructor's guidance of about three seconds, and a per-check timing table is published. The shell lint measured 22.0 s on a 44-file commit; it now lints files in parallel and turns dataflow analysis off only for scripts over 2,000 lines, 3.0 s on the same commit, and those scripts' dataflow checks run with full analysis as `lint-full` (11.8 s on that commit) in the pre-PR check and CI rather than being dropped | [#16645](https://github.com/melodic-software/claude-code-plugins/pull/16645), [#16906](https://github.com/melodic-software/claude-code-plugins/pull/16906), [#18205](https://github.com/melodic-software/claude-code-plugins/pull/18205) |
| The check's failure text tells the agent what to do | Puts guidance in the error, not up front | Inference: guidance read at failure time is read when it matters | Same | **already have**: a codify proposal requires the check's message to name the fix | [#16603](https://github.com/melodic-software/claude-code-plugins/pull/16603) |
| A file-size cap counted in estimated tokens | Fails a file that grows past a size | Inference: agents build files too large to navigate | No study found ties file size to agent outcomes, and a byte-based token estimate is not a token count | **adapt**: the pre-PR check and CI fail a change in which a file crosses `size.file_lines` (`size.check: crossing` in `docs/conventions/code-metrics.yaml`), counted in non-blank lines, not estimated tokens; a file already over the reference does not fail | [#17251](https://github.com/melodic-software/claude-code-plugins/pull/17251) |
| Keep the prose rule beside the new check | Leaves the rule in the standards file too | Inference: the agent should know the rule before tripping it | A rule a check enforces, also written in prose, drifts from the check | **reject**: prose is for what no check can enforce | none |
| A format check in the pre-commit hook | Fails a commit whose staged files are not formatted | Inference: unformatted code should not reach a commit | The formatter that runs once per batch of agent edits (ADR 0072) already formats what an agent writes; when this was decided, the shipped pre-commit set also measured 96.3 s on a 44-file commit, over the commit budget ([Per-check timings](../contracts/check-placement/README.md#per-check-timings)), most of it the shell lint the commit-budget row above speeds up | **reject**: this repository's pre-commit stage gets no formatter check; the once-per-batch formatter stays | none |
| Skip the hook once for a mass reformat | Bypasses the hook with the owner's consent | Inference: a first reformat touches every file | Every git hook can be bypassed, so CI is the hard stop | **already have**: `guardrails` blocks hook-skipping flags and hook-manager skips on commit and push | none |
| Hooks in a team repository, and a teammate's way out | n/a (raised while absorbing) | n/a | Checks an agent fixes at once land on teammates who write by hand, and a quick per-person skip would weaken every check | **already have**: the one skip is `checks.skipmissing`, honored only for a tool that is absent and printed as `SKIPPED:` ([The skip key](../contracts/check-placement/README.md#the-skip-key-checksskipmissing)); there is no per-person skip; `guardrails` `block-no-verify` keeps blocking other skips; CI re-runs every check; a format or lint hook runs only on files the tool's own committed config opts in, so team rules apply once the team commits that config | none |
| A skill that sets up a pre-commit hook | Installs a hook manager and a staged-files runner, with formatting, type checks and tests at commit | Inference: each repository otherwise hand-writes its hooks | Re-judged against our own installer | **reject**, as [mattpocock-skills.md](mattpocock-skills.md) records for `setup-pre-commit`: the shared git-hooks installer (ADR 0072, with `inspect` from [#16627](https://github.com/melodic-software/claude-code-plugins/pull/16627)) installs and inspects hooks under any hook manager, and this repository's pre-commit stage gets no formatter check (the format-check row) | none |

### Speeding up checks

| Idea | What it does | Upstream problem | Our problem | Disposition | Landed |
|---|---|---|---|---|---|
| Check speed matters more than people expect | Treats slow checks as slow agent feedback | Inference: every wait on a check is a wait for the agent | We had no ranking of which checks cost the most per lane | **adapt**: `performance` ranks slow checks per lane and `toolchain:ratchet` holds their growth; the shell lint was made faster on the same evidence, first by linting each distinct staged file once, then by parallel lanes with the dataflow checks of scripts over 2,000 lines moved to the pre-PR check and CI | [#16648](https://github.com/melodic-software/claude-code-plugins/pull/16648), [#16659](https://github.com/melodic-software/claude-code-plugins/pull/16659), [#16906](https://github.com/melodic-software/claude-code-plugins/pull/16906) |
| Keep the old version for a tool the upgrade breaks | Pins an older release beside the new one for a tool that loads it | Inference: a new major version drops an API another tool depends on | A faster tool can break another tool that loads it | **adapt**: an upgrade or swap `performance:target` proposes carries a dependency-collision check, read from the package manager's dependency tree | [#16648](https://github.com/melodic-software/claude-code-plugins/pull/16648) |
| Swap slow tools for faster native ones | Replaces a formatter and a type checker with faster builds | Inference: the tool, not the check, is slow | Naming a tool in a shipped skill ties every consumer to it | **no change**: skills ship no per-stack tool advice; stack specifics are researched at run time against the consumer's own setup, a rule recorded in the plugin philosophy and held by a ratchet on stack-specific code fences | [#16634](https://github.com/melodic-software/claude-code-plugins/pull/16634), [#16649](https://github.com/melodic-software/claude-code-plugins/pull/16649) |
| A green check that inspected nothing | Reads what a check did, not its color | Inference: a check over zero inputs passes and means nothing | Our passes could exit 0 with nothing to inspect | **adapt**: an empty diff while HEAD is not the base, or a sharded test leg that draws no suite, fails; a change with nothing a check applies to reports "not applicable" | [#16645](https://github.com/melodic-software/claude-code-plugins/pull/16645) |
| Run hook jobs in parallel | Runs several checks at once and reports each failure | Inference: serial checks waste the budget | A bare `wait` returns 0, so a script that does not track each job loses a failed one | **already have**: the affected-checks runner takes a job count. An audit of our parallel scripts found bare-`wait` sites in tests, a measurement script and a documented example where a failed background job was lost; each now waits on every job by pid or records its status, so a failure surfaces (vendored text and a planted eval defect left as they are) | [#16895](https://github.com/melodic-software/claude-code-plugins/pull/16895) |
| Tests out of git hooks and into CI; no pre-push hook | Keeps local hooks to fast checks | Inference: a growing suite slows every push | Every hook can be skipped, and one check must stop a leak before it reaches a public repository | **adapt**, mostly as the course says: pre-push keeps only the secrets and machine-path scan, within the 3 s hook budget; the boundary and lint checks run in the pre-PR check or CI; tests stay in CI, since change-scoped tests measured 90.7 s to 145.7 s ([Per-check timings](../contracts/check-placement/README.md#per-check-timings)); CI stays the hard stop | [#16645](https://github.com/melodic-software/claude-code-plugins/pull/16645), [#18205](https://github.com/melodic-software/claude-code-plugins/pull/18205) |

### A custom lint rule

| Idea | What it does | Upstream problem | Our problem | Disposition | Landed |
|---|---|---|---|---|---|
| A narrow rule beats banning an API | Forbids the unsafe use of a call, not the call | Inference: a ban blocks legitimate uses | Same | **already have**: codify's pattern-rule and custom-analyzer rungs | none |
| An agent writes the rule | Has the agent author the lint rule | Inference: rules are cheap to write now | An untested rule may match too little; nothing says what it misses | **adapt**: a rule codify proposes ships with valid and invalid rule tests and states what it does not catch | [#16633](https://github.com/melodic-software/claude-code-plugins/pull/16633) |
| Rules a team can live with | Surveys legitimate uses before scoping a rule | Inference: an over-strict rule gets its author blamed | Exclusions can hide a problem | **adapt**: a safe-team-rules reference in codify (survey the uses, scope the rule, justify every exclusion) | [#16633](https://github.com/melodic-software/claude-code-plugins/pull/16633) |
| Format and lint plugins fixed to one tool | n/a (raised while absorbing) | n/a | Our format and lint plugins pick the tool, which may not fit a consumer and goes stale | **adapt**: format and lint plugins resolve the tool per repository, with formatting and linting kept apart. Their hooks (the once-per-batch formatter and the `format` and `lint` git-hook entries) run only the adapter each plugin ships, on files the tool's own config opts in, and run no lint autofix. A repository's `docs/conventions/ecosystems/<id>.yaml` record runs only when a person asks `/toolchain:lint` or `/toolchain:check`, since no check of a record's contents can bound what its command executes ([Hooks run the shipped adapter](../contracts/check-placement/README.md#hooks-run-the-shipped-adapter)). That supersedes an earlier choice to let a record matching the default branch run from a hook | [#16670](https://github.com/melodic-software/claude-code-plugins/pull/16670), [#16707](https://github.com/melodic-software/claude-code-plugins/pull/16707), [#16710](https://github.com/melodic-software/claude-code-plugins/pull/16710), [#16711](https://github.com/melodic-software/claude-code-plugins/pull/16711), [#16713](https://github.com/melodic-software/claude-code-plugins/pull/16713), [#16714](https://github.com/melodic-software/claude-code-plugins/pull/16714), [#16715](https://github.com/melodic-software/claude-code-plugins/pull/16715), [#16717](https://github.com/melodic-software/claude-code-plugins/pull/16717) |

### Mutation testing

| Idea | What it does | Upstream problem | Our problem | Disposition | Landed |
|---|---|---|---|---|---|
| Mutation testing grades the tests, not the code | Reads a surviving mutant as a weak test | Inference: coverage says a line ran, not that a test checks it | Same | **already have**: [`/mutation-testing:principles`](../../plugins/mutation-testing/skills/principles/SKILL.md) | none |
| Mutate only the changed lines | Keeps a mutation run fast | Inference: a whole-repository run takes hours | Same | **already have**: `/mutation-testing:audit` runs on the diff by default | none |
| Run it before the change is reported done, and fix survivors | Puts mutation in the agent's own verification | Inference: survivors found after merge are rarely fixed | Ours ran only after merge | **adapt**: `/implementation:implement` ends with a diff-scoped mutation run, advisory, survivors persisted for a fix pass | [#16614](https://github.com/melodic-software/claude-code-plugins/pull/16614) |
| A survivor as a test-quality signal | Uses mutation results to inform the agent, without failing a build | Inference: a score threshold invites gaming | `/testing:test-value` did not name mutation | **adapt**: test-value names a surviving mutant as one weak-test signal and points to `mutation-testing` | [#16610](https://github.com/melodic-software/claude-code-plugins/pull/16610) |
| Plant specific defects to see if the tests catch them | n/a (carried over from the codebase-design workshop) | n/a | No skill planted realistic defects on purpose | **take**: a `seed-faults` action plants defects in a throwaway worktree and reports caught over planted, with each survivor's location; nothing it plants is committed | [#16632](https://github.com/melodic-software/claude-code-plugins/pull/16632) |
| Equivalence calls made in the conversation | Calls some survivors equivalent without recording why | Inference: a judgment no file holds cannot be re-checked | An equivalence call reached only the human-facing report | **adapt**: each demonstrated equivalent mutant is written with its demonstration to the findings file, in a section the fix action does not parse, under a detector-findings contract addition | [#16916](https://github.com/melodic-software/claude-code-plugins/pull/16916) |
| A mutation skill tied to one tool and one repository's scripts | Hard-codes the tool and report format | Inference: a skill written for one project | A shipped skill must fit any consumer | **reject** the hard-coding: `mutation-testing` takes the tool from repository config. The pattern behind it is recorded: a shipped skill generates a repository-specific skill only where config cannot express the difference | [#16612](https://github.com/melodic-software/claude-code-plugins/pull/16612) |
