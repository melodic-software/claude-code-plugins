# Path classes that carry NO shell test suite (**/*.test.sh), each paired with
# the CI lane that DOES cover it. Read by scripts/affected-tests.sh, which
# treats a changed file matching one of these as "covered, but not by a shell
# suite" instead of the loud "I do not know what covers this" error.
#
# Consulted LAST — only after every selection rule has come up empty for the
# file. A doc or manifest that a suite genuinely names is still selected by the
# reference rule, so listing a broad pattern here never suppresses a real match.
#
# This list is deliberately SEPARATE from scripts/docs-only-paths.txt even
# though the two overlap. They answer different questions: docs-only asks "can
# this path affect ANY code lane" (a very narrow yes, because a wrong answer
# turns CI false-green), while this asks "is there a SHELL SUITE covering this"
# (a broader yes, because a wrong answer only costs a developer a needless
# error). Coupling them would drag the narrow gate's answer into the wrong
# question. Keep both; do not make one read the other.
#
# Format: one bash glob pattern per line, matched against the repo-relative
# path. `*` crosses `/`. Blank lines and `#` comments are ignored. Adding an
# entry is a claim that a named non-shell lane covers the class — write the
# lane in the comment above it, the way every other data file in scripts/ does.
#
# ADDING A NEW CODE FILE? Do not reach for this list. A new .sh/.py/.mjs with
# no coverage should FAIL here; that failure is the tool working.

# Markdown prose — skills, references, conventions, design records, changelogs.
# Covered by the hygiene lane (markdownlint-cli2, typos, comment-hygiene,
# machine-specific-paths, lychee) and, for skill bodies, by skill-quality-gate
# (check-skill.sh, check-listing-budget.sh). None of those is a *.test.sh.
*.md

# JSON — plugin/marketplace manifests, JSON Schemas, eval graders, registries,
# lockfiles. The validators here are FILE-SCOPED, so read the SCOPES rather than
# the tool names: check-jsonschema covers .claude-plugin/marketplace.json,
# plugins/*/.claude-plugin/plugin.json, .github/dependabot.yml and five named
# workflow files; scripts/check-manifest-duplicate-keys.py covers those same
# plugin and marketplace manifests and nothing else; skill-quality-gate covers
# plugins/*/skills/*/evals/evals.json; scripts/validate-plugin-contracts.mjs
# reads only under plugins/, and its JSON reach there is plugins/**/*.schema.json
# plus .md/.json under plugins/*/skills/setup/ and the ai-briefing tree.
#
# Every OTHER .json in the repo — .github/recurring-schedule.json, the
# docs/conventions/hook-telemetry/data/*.schema.json set, the runner-policy
# tree — is a DATA file whose only gate is that something parses it. That is a
# real but thin lane, and it is deliberately what this entry claims: no shell
# suite covers JSON, and none should have to. A JSON fixture a suite actually
# names is selected by the reference rule before this line is ever consulted.
*.json

# Workflows and repository configuration — every path here is CONSUMED by a
# lane that fails when the file is malformed, which is the coverage being
# claimed. .github/* is read by actionlint, zizmor, the workflow and dependabot
# check-jsonschema steps, and the runner-policy lane; the dotfiles and *.toml
# configure the hygiene-lane tools that read them (editorconfig-checker,
# shellcheck, gitleaks, typos, lychee, ruff), so a broken one fails its own
# tool's step.
#
# There is deliberately NO bare *.yaml / *.yml entry. Both used to be here, and
# both were a coverage claim this repo could not honor. Every .yml in the repo
# already sits under .github/*, so the entry bought nothing; *.yaml additionally
# swept in 13 files that NO lane reads —
# plugins/toolchain/reference/ecosystems/*.yaml (9) and
# docs/conventions/ecosystem-commands/examples/*.yaml (4). Verified absent, not
# merely unattributed: there is no yamllint step anywhere in .github or scripts;
# every check-jsonschema step names its files and none names these;
# validate-plugin-contracts.mjs does not mention yaml at all; and
# `git ls-files 'plugins/toolchain/**/*.test.sh'` is empty. The generic hygiene
# steps (typos, editorconfig-checker, gitleaks) read the bytes but validate
# nothing about these files' contract. So they now fail loud, which is this
# tool working. To bring them back, give them a real lane first: they have a
# schema already — docs/conventions/ecosystem-commands/ecosystem.schema.json —
# and wiring a check-jsonschema step against it is the natural way to earn an
# entry here.
.github/*
.gitattributes
.gitignore
.editorconfig
.shellcheckrc
.node-version
*.toml

.work/*
