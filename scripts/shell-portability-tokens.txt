# Shell-portability-lint token list (issue #1491). Each ACTIVE line is one ERE
# pattern that scripts/check-shell-portability.sh matches, line-by-line, against
# changed **/*.sh files. Detects GNU-only constructs that a BSD userland (macOS
# system grep/sed/date/stat/mktemp/sort — the one platform no CI runner in this
# repo covers; a Windows runner's Git Bash still ships GNU grep/sed) either
# rejects outright or silently reinterprets. The motivating near-miss: a
# `grep -Eq '\brequire\b'` word-boundary escape in
# plugins/markdown-format/hooks/markdown-format.sh would have made a security
# predicate fail OPEN (return "nothing unpinnable found" for every input) on
# BSD grep, with no test on a GNU runner able to catch it. The fix (now on
# main) is the reference implementation this gate self-tests against.
#
# Ownership / growth: this list is the gate's data, deliberately kept OUT of the
# script — the same shape as scripts/skill-portability-tokens.txt for the
# sibling portability-lint gate (#531) — so a reviewer re-catch of a GNU-only
# construct is a one-line data change, never a gate-logic edit.
#
# Format: blank lines and lines beginning with `#` are ignored; every other
# line is an ERE pattern (leading/trailing whitespace trimmed), matched against
# each non-comment line of a scanned file (a `#`-prefixed line, after leading
# whitespace, is never scanned for constructs — the class this gate detects is
# live command syntax, not prose; several legitimate dual-dialect comments in
# this corpus mention `date -d` / `grep -P` by name only to explain why the
# GNU/BSD branch below them exists). Labels live in the comment above each
# pattern, never on the pattern line.
#
# Escaping a legitimate hit (see the script header for detection detail):
#   - an auto-recognized same-line BSD-counterpart guard (readlink -f tried
#     only as the `||` fallback after a co-located realpath attempt);
#   - a per-site recorded exemption: `portability-ok: <reason>`.
# Direction is deliberately over-flag, not under-flag (see the linked issue's
# "Two design notes"): a justified false positive costs a reviewer one line: a
# missed true positive can ship a silent fail-open security predicate.

# --- ACTIVE ---

# GNU-only regex word-boundary/class escapes inside a grep/sed pattern. POSIX
# ERE/BRE define no `\b`/`\<`/`\>`/`\s`/`\S`/`\w`/`\W`; BSD grep/sed either
# rejects them or (worse) reads `\b` as a literal `b`, silently turning
# `\brequire\b` into `brequireb` — matches nothing, exactly the near-miss above.
# Each token matches the literal two-character escape sequence, with NO
# required co-located `grep`/`sed` on the line. Requiring one was tried and
# reverted: a pattern is very often built on its own line and consumed
# several lines later, so the requirement silently un-catches exactly the
# near-miss shape above. The live proof is in this repo —
# plugins/claude-config/skills/audit-instructions/scripts/instruction-scan.sh
# assigns `\b`-bearing EREs to I6_ERE/RATIONALE_ERE and only later passes
# them to `grep -niE`; a grep/sed-context requirement reports that file
# clean. The cost of staying bare is the mirror-image false positive: the
# same two characters are also legitimate, portable `printf`/`$'...'`
# escape-sequence syntax (`printf '\b'` — a real backspace byte, identical
# on GNU and BSD), which this list DOES flag. That is the documented
# over-flag direction, and `portability-ok: <reason>` is the one-line escape
# for it. Narrowing the class precisely — knowing which operand of which
# command is a regex — needs real shell parsing, not a token edit; tracked
# in #1517.
\\b
\\<
\\>
\\s
\\S
\\w
\\W

# `grep -P` (PCRE mode) — absent in BSD grep, and in some GNU builds compiled
# without PCRE support. `P` may appear anywhere in a combined short-option
# cluster (`-riP`, `-nP`), not only as the cluster's last letter.
grep[^\n]*[[:space:]]-[A-Za-z]*P[A-Za-z]*([[:space:]]|$)
--perl-regexp

# `echo -e` — POSIX leaves echo's flag handling unspecified; BSD/macOS sh/bash
# builtin `echo` treats `-e` as a literal argument, not an escape-interpretation
# flag. `printf '%b\n'` (or a literal `$'...'` ANSI-C string) is the portable
# replacement. `e` may appear anywhere in echo's short-option cluster
# (bash advertises `echo [-neE]`), not only as a standalone `-e`.
echo[[:space:]]+-[a-zA-Z]*e[a-zA-Z]*([[:space:]]|$)

# `sort -V` (natural/version sort) — a GNU coreutils extension; BSD sort has no
# `-V`. `V` may appear anywhere in a combined short-option cluster (`-Vr`),
# not only as the cluster's last letter. `--version-sort` and `--sort=version`
# are GNU's documented long-form spellings of the same option (man7.org
# sort(1): "-V, --version-sort" and "--sort=WORD ... version -V").
# `--version-sort` is an unambiguous literal, so (like --perl-regexp above) it
# needs no command-context prefix. `--sort=WORD` is NOT: `git tag`,
# `git for-each-ref` and `git branch` all take a portable `--sort=<key>`, whose
# keys include `version:refname`. So that spelling carries the same
# `sort`-command prefix the short-flag pattern uses, and requires a boundary
# after the WORD (else `version:refname` matches as a prefix). That boundary is
# every character that can actually END a shell word — whitespace, a control
# operator, a redirection, a subshell close, a quote — or end of line, so the
# no-whitespace forms (`$(sort --sort=version)`, `... |head`, `...; echo`) are
# matched, while a longer word like `version:refname` still is not. WORD is a
# MANDATORY argument, so GNU's getopt_long takes it attached after `=` or as
# the next argv element, and the shell may hand it over quoted — every one of
# those spellings is the same GNU-only operation.
sort[^\n]*[[:space:]]-[A-Za-z]*V[A-Za-z]*([[:space:]]|$)
--version-sort
sort[^\n]*[[:space:]]--sort(=|[[:space:]]+)['"]?version([[:space:]|&;()<>'"`]|$)

# `sed -i` with no suffix argument attached — GNU treats the suffix as
# optional; BSD sed requires one immediately after `-i`. This intentionally
# ALSO flags the space-separated empty-suffix idiom (`-i ''` / `-i ""`): it
# looks BSD-safe but is not actually portable — verified against a real GNU
# sed 4.9, that exact invocation exits 2, because GNU consumes the
# space-separated empty string as sed's SCRIPT argument, silently shifting
# the real script and target file to be opened as filenames. The one
# genuinely dual-compatible spelling is an ATTACHED nonempty suffix
# (`sed -i.bak '...' file && rm -f file.bak`), which this token does not
# match (no separating whitespace) — correctly never flagged. Still does not
# cover an attached-not-space-separated EMPTY suffix (`-i''`) — ambiguous
# with BSD's own attached-suffix syntax, needs real sed-dialect research
# before encoding, not a quick pattern tweak — see #1513.
sed[^\n]*-i[[:space:]]+[^[:space:]]

# `sed -Ei` (extended-regex and in-place combined into one short-flag cluster,
# with `-i` UNSUFFIXED) — the `-i[[:space:]]+[^[:space:]]` token above only
# catches a literal standalone `-i`; it does not match a cluster like `-Ei`
# (no literal `-i` substring — the char after `-` is `E`, not `i`). `E` and
# `i` need not be adjacent and need not be the cluster's only letters
# (`-nEi`), mirroring the combined-cluster treatment #1511 already applies to
# `grep -P` / `sort -V` / `echo -e` — but `i` MUST be the cluster's last
# letter. GNU's own syntax is `-i[SUFFIX]`, so any letter after `i` is an
# attached backup suffix, not another option: `sed -iE` writes `fileE`
# (verified against a real GNU sed 4.9), making it the dual-compatible
# attached-nonempty-suffix form, correctly never flagged — same as `-i.bak`
# and `-Ei.bak`. An attached EMPTY suffix (`-Ei''`) is the same ambiguous
# shape `-i''` is, deferred above, and likewise not flagged here. Anchored to
# a `sed` COMMAND token (start of line or a non-identifier character before
# it, whitespace after) — `-i` alone is common across tools (`grep -i`,
# `sort -i`...), and a bare `sed` substring match would fire on identifiers
# that merely contain those three letters (`used="$(grep -Ei ...)"`).
(^|[^[:alnum:]_])sed([[:space:]][^\n]*)?[[:space:]]-[A-Za-z]*E[A-Za-z]*i([[:space:]]|$)

# `sed --in-place[=SUFFIX]` (GNU long-form spelling of `-i`) — BSD sed has no
# long options at all, so this flags suffixed or not (unlike short `-i`, where
# BSD requires an attached suffix and only the unsuffixed form is GNU-only,
# `--in-place` has no portable BSD equivalent in either shape). Scoped to a
# `sed` command token for the same reason as the cluster token above: unlike
# `--perl-regexp` / `--version-sort`, the option name `--in-place` is not
# unique to one tool (several formatters spell their own in-place flag that
# way), so a bare token would flag a script that merely defines or forwards an
# unrelated `--in-place` option of its own.
(^|[^[:alnum:]_])sed([[:space:]][^\n]*)?[[:space:]]--in-place([[:space:]]|=|$)

# `readlink -f` (canonicalize) — a GNU coreutils extension; BSD/macOS readlink
# has no `-f`/`--canonicalize`. Auto-guarded when a `realpath` attempt is
# ACTUALLY WIRED as its fallback via `||` on the same line (the pattern this
# repo's own lib/hook-utils.sh already uses: `realpath ... || readlink -f
# ...`) — a realpath call merely mentioned nearby with no `||` relationship
# (e.g. two unconditional statements in sequence) still flags.
readlink[[:space:]]+(-[A-Za-z]*f|--canonicalize)

# `date -d` (GNU date-string parsing) — a GNU coreutils extension; BSD/macOS
# date has no `-d`. Requires whitespace immediately after `date` so the token
# matches only the actual command invocation, not an identifier that merely
# contains "date" as a substring followed later by an unrelated ` -d` flag on
# the same line (e.g. `[[ -d "$candidate" ]]` — "date" inside "candidate").
# The one real dual-dialect site
# (plugins/claude-ops/skills/morning-brief/scripts/morning-brief.sh
# to_epoch/from_epoch) tries GNU `date -d` then BSD `date -j -f`/`date -r`
# across separate statements, not co-located on one line, so it is excused via
# a `portability-ok:` annotation at each site rather than a same-line guard
# (#1510).
date[[:space:]]+[^\n]*-d([[:space:]]|$)

# `stat -c` (GNU format string) — a GNU coreutils extension; BSD/macOS stat
# uses `-f`. Requires whitespace immediately after `stat` so the token matches
# only the actual command invocation, not an identifier that merely starts
# with "stat" (e.g. "status") followed later by an unrelated ` -c` flag on the
# same line (git's own `-c name=value`, a common corpus pattern in this
# repo's own guardrails test fixtures: `git -c alias.x=status -c ...`).
# Auto-guarded when a co-located `stat -f` attempt sits on the same line (the
# shape plugins/repo-hygiene/skills/clean/scripts/remove-path.sh dev_of()
# already uses: `stat -c ... || stat -f ...`). The two plugins/kindle-dedrm
# sites have no BSD fallback but are excused via `portability-ok:` — that
# plugin's scripts are Windows-only (Git Bash + PowerShell + LOCALAPPDATA), so
# a BSD fallback there would be dead code (#1510).
stat[[:space:]]+[^\n]*-c
