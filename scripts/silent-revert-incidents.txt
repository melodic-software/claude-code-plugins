# Recorded incidents for scripts/check-silent-revert.sh --verify-known-incidents.
#
# This file is the canary's honesty proof. A detector that merely looks
# plausible is worthless against #2691, because the whole reason that incident
# went unnoticed for hours is that every signal a reader normally checks --
# merged PR, closed issue, green CI, no `Revert:` commit -- looked healthy. So
# the shipped thresholds are replayed against the ACTUAL merges every time the
# canary runs, and must still reproduce them.
#
# The `clean` rows matter as much as the `fires` rows. A detector tuned until
# it catches the incidents but which also fires on ordinary work would be
# switched off within a week, so a verified-legitimate commit is pinned here
# too -- deliberately the closest sub-threshold miss found in 500 commits of
# real history, since that is the row that breaks first if someone lowers the
# threshold to chase recall.
#
# Format: <expectation> <full-sha> [<attribution>] <note>. `fires` = the canary
# must report a finding; `clean` = it must not. Blank lines and `#` lines
# ignored.
#
# The bracketed ATTRIBUTION field is what makes a `fires` row an assertion
# rather than a claim (#2833). Without it the replay proved only that the
# commit still produces SOME finding, while the note beside it named a specific
# culprit and a specific line count that nothing checked. On the cc58cbc53 row
# that gap was load-bearing: its deletions trace to two culprits, so losing the
# eda5ae5ed attribution entirely would still have printed `ok` on the surviving
# bfb66beb8 finding -- the canary announcing a reproduction it did not perform.
#
#   [<culprit-full-sha>=<blamed-lines>,<culprit-full-sha>=<blamed-lines>]
#
# The replay asserts the run's findings are EXACTLY this set: same culprits,
# same per-culprit counts, no extras and no omissions. Full 40-character
# culprit shas only, the same discipline silent-revert-acknowledged.txt uses.
# The field is optional -- a row can be pinned before its attribution is
# measured -- but every `fires` row below carries one, and a malformed field is
# exit 2 rather than a failure or a pass.
#
# Every count is a BLAME ATTRIBUTION: the number of lines the reverting squash
# deleted that `git blame` credits to that one culprit. Not the squash's
# diffstat, and not what the culprit itself added.
#
# Do NOT relax a row to make CI pass, and do NOT loosen a count to a minimum or
# a tolerance. A row that no longer holds means the canary stopped detecting the
# thing it exists to detect; fix the canary. If a number legitimately moves,
# measure the new one and record why -- that is a decision, not a threshold.
